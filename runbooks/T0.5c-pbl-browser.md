# Runbook T0.5c — Turn PBL on in the browser build (worker t05)

Read `runbooks/_wave7-common.md` first. Report: `reports/T0.5c.md`. Logs: `runs/T0.5c/`.

## Background (supervisor)
T0.5b (`reports/T0.5b.md`) fixed SpiderMonkey's portable baseline interpreter (PBL): the Node
replay is exact 3/3 and 1.45x faster. The browser build still forces it off in
`tools/wasm/web-env.pre.js:11-14` (`ENV.JIT_OPTION_portableBaselineInterpreter = 'false'`).
Before T0.5b, PBL in the browser crashed a long observer match at ~22 min (log L33/T0.6c).

## Files you may edit
- `tools/wasm/web-env.pre.js` (only that block)
- new: `runs/T0.5c/*`

## Step 1 — Enable PBL by default, keep an opt-out
Replace the block's comment and line with: PBL on by default; the page query `?pbl=0` turns it
off (read how `web-env.pre.js` already reads the page query, e.g. for `replay`, and do it the
same way). Comment: PBL is on since the backport of upstream bug 1909656 (T0.5b); `?pbl=0`
keeps the old C++-interpreter path for comparison.

## Step 2 — Build the web engine (engine lock)
`WORKER=t05 tools/wasm/with-lock.sh sh -c 'WASM_PROFILE=web tools/wasm/build-engine.sh > runs/T0.5c/build.log 2>&1; s=$?; if [ $s -eq 0 ]; then rm -r runs/web-t05 2>/dev/null; cp -RP upstream/binaries/system-web runs/web-t05; fi; exit $s'; echo EXIT=$?`

Expected: both EXIT=0 (local hash `6908836f8d8ca50562faab971ad0c4ca`, remote
`5428b90a27ecd769cd3d76b38ddb11dd`). Report the replay wall time of each (from the logs) and,
if the logs print per-turn times, p50/p99/max.
