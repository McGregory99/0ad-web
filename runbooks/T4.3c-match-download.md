# Runbook T4.3c — What the 426 MB before the first match are (worker t41, port 8102)

Read `runbooks/_wave5-common.md` first. Report: `reports/T4.3c.md`.

Context (your T4.3b): a first visit streams 28 MB to reach the menu, then +426 MB in 952 requests to
start a skirmish (cached reload: +73 MB). Goal: list which files and which byte ranges make up that
426 MB, and how much of it is over-fetch (bytes downloaded but never read).

Allowed edits: `tools/wasm/web-lib.js` only, and only an opt-in log that is OFF unless the page URL
has `remotelog=1`. Do not change how reads work.

## Step 1 — Read how remote reads work (no edits)
```bash
grep -nE 'remoteStats|Range|fetch\(|chunk|CHUNK|block|BLOCK|caches|persistent' tools/wasm/web-lib.js | head -60
```
Write in the report: the fetch unit size (chunk/block), whether a read of N bytes fetches more, and
how a zip member is located (central directory? per-file offsets?).

## Step 2 — Add an opt-in per-path log
Where a remote read is served, when `new URLSearchParams(location.search).get('remotelog') === '1'`,
add to a global `Module.remoteLog` map: key = file path inside the zip (or URL), value =
`{ reads, bytesRead, bytesFetched }` (bytesRead = what the engine asked for; bytesFetched = what
went over the network for it). Expose nothing else. Rebuild (web build command from
`_wave5-common.md`, task name T4.3c), EXIT must be 0.

## Step 3 — Measure a first visit to a match
Write `runs/T4.3c/dump.js`:
```js
(() => { const m = Module.remoteLog || {}; return JSON.stringify(Object.entries(m)); })()
```
Run:
```bash
CHROME_GPU=1 perl -e 'alarm shift; exec @ARGV' 300 node tools/web/chrome-shot.mjs runs/web-t41 runs/T4.3c/first \
  "wait:25,stats,evalfile:runs/T4.3c/dump.js,$START,wait:60,stats,evalfile:runs/T4.3c/dump.js,shot:game" \
  "?arg=-mod=public&arg=-conf=windowed:true&remotelog=1" 8102
```
Save the second evalfile JSON to `runs/T4.3c/match.json` (copy it out of console.log).
With a small Node script in `runs/T4.3c/` compute and paste into the report:
1. Top 40 paths by bytesFetched (path, reads, bytesRead, bytesFetched).
2. Totals grouped by extension (.dds .png .pmd .dae .xml .ogg .json .js .xmb .cached .other).
3. Totals grouped by top folder (art/textures, art/meshes, audio, maps, simulation, gui, ...).
4. Sum bytesRead vs sum bytesFetched (over-fetch %).
5. Do textures come as source .png/.tga that the engine converts at runtime, or as cached .dds? Count both.
