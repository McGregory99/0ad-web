## e2e.mjs (usage, PASS rule)

New file `tools/web/e2e.mjs` (147 lines).

Usage: `node tools/web/e2e.mjs <build dir> <outdir> [port]` — port defaults to `8107`.
Env: `E2E_BROWSERS` (comma list, default `chrome,firefox`), `E2E_MIN_FPS` (default `30`),
`E2E_MATCH_WAIT` (seconds in the match before measuring fps, default `40`).

What it does — **observed** by reading the code and by the runs below:
- Builds one scenario string from `E2E_MATCH_WAIT`:
  `wait:25,shot:menu,click:491:553,wait:2,click:180:221,wait:3,click:418:221,wait:8,click:1185:681,wait:<E2E_MATCH_WAIT>,stats,fps:10,shot:game`
  with the query `?arg=-mod=public&arg=-conf=windowed:true` (1280x720 viewport, the shot tools' default).
- Runs `tools/web/chrome-shot.mjs` / `tools/web/firefox-shot.mjs` as `spawn('node', ...)` children,
  sequentially (one browser at a time, `await` on exit), with `<outdir>/<browser>` as the shot tool's outdir
  and the port from the CLI; Chrome gets `CHROME_GPU=1` in its env. The child's stdout/stderr go to
  `<outdir>/<browser>/tool.log`.
- Parses `<outdir>/<browser>/console.log`: `reachedMatch` (a `GAME STARTED` line), the fps JSON
  (`frames`, `fps`, `p50`, `p99`, `max`, each `null` if absent), and error lines. Level parsing is
  `exception` **or** `error` **or** `*/error` (covers chrome's `network/error` and Firefox's `error`),
  first 20 kept as `errorLines`; `exceptionLines` (also first 20) is the subset that must be empty for a
  PASS. Lines containing `Cannot read properties of null (reading 'init')` are not added to `errorLines`
  and are counted in `knownAiWorkerError`.
- Writes `<outdir>/summary.json`: `{build, port, minFps, matchWait, steps, query, browsers: {<browser>: {...}}, pass}`,
  one object per browser holding `toolExitCode`, `pass`, `reasons`, `reachedMatch`, `fps`, `frames`, `p50`,
  `p99`, `max`, `errorLines`, `exceptionLines`, `knownAiWorkerError`, `outdir`, `startedAt`.
- Prints one line per browser (`chrome: PASS fps=60.1 (p99=16.7 max=16.7)` or `firefox: FAIL (reason1; reason2)`),
  then the summary path and `PASS=true|false`.

PASS rule per browser (all four must hold): shot-tool exit code 0; a `GAME STARTED` line; measured
`fps >= E2E_MIN_FPS`; zero `exception` lines. Error lines such as the harmless 404 do not fail a browser
(they are reported in `summary.json`). Exit code 0 only if every selected browser passed, 1 otherwise,
2 on bad usage.

`node --check tools/web/e2e.mjs; echo EXIT=$?` → `EXIT=0` — **observed**.
