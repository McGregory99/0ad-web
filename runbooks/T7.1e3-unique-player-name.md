# Runbook T7.1e3 — Each browser player gets its own default name (worker t71e3)

Read `runbooks/_wave7-common.md` first. Report: `reports/T7.1e3.md`. Logs: `runs/T7.1e3/`.
Ports: http 8109, relay 20640 (same as t71e; t71e is finished).

## Background (supervisor)
`reports/T7.1e2.md` (read its "Three fixes" section) found that in the browser
`Engine.GetSystemUsername()` is always `web_user`, so the join and host dialogs default every
player to `web_user` (`multiplayerName()` in `gui/common/functions_utility.js` returns
`playername.multiplayer` or the system user name). The server then rejects the second player
with `NDR_PLAYERNAME_IN_USE` (`reason:8`). Real users would hit this every time. mp-check's
`MP_GUI` mode works around it with `-conf=playername.multiplayer:client`
(`tools/web/mp-check.mjs:319-322`).

## Step 1 — Pure function + tests
Read `web_roomcode.js` and `roomcode.test.mjs` first. Add a pure function (no `Engine`):
`webDefaultPlayerName(current, systemName, random)` → string:
- if `current` (trimmed) is non-empty and different from `systemName` → return `current`
  unchanged (the user chose a name or saved one);
- otherwise → `"Player " + n` where `n` is a 4-digit integer 1000..9999 from `random()`
  (a function returning [0,1)).
Tests: `("Ana","web_user",r)` → `"Ana"`; `("web_user","web_user",()=>0)` → `"Player 1000"`;
`("","web_user",()=>0.99999)` → `"Player 9999"`; `("  ","web_user",()=>0.5)` → `"Player 5500"`.
`node --test tools/wasm/web/roomcode.test.mjs > runs/T7.1e3/unit.log 2>&1; echo EXIT=$?` → 0.

## Step 2 — Use it in the dialog (only when webnet.relay is set)
Find the extracted original `gui/gamesetup_mp/gamesetup_mp.xml` / `.js`
(`D=$(mktemp -d); unzip -o -q data/mods/public/public.zip 'gui/gamesetup_mp/*' 'gui/common/functions_utility.js' -d "$D"; echo $D`;
never extract into the repo) and find the name fields of the host and join pages
(the `<action on="Load">` that calls `multiplayerName()`). In `web_roomcode.js`, in the same
place where the room-code overrides already run at init, set each name field's caption to
`webDefaultPlayerName(caption, Engine.GetSystemUsername(), Math.random)`. Do not save it to the
config. Native builds (empty `webnet.relay`) must be unaffected.

## Step 3 — Remove the mp-check workaround, build, test
In `mp-check.mjs` make the `MP_GUI` client page use the plain base query (delete the
`-conf=playername.multiplayer:client` workaround and its comment). Then:
```bash
mkdir -p runs/T7.1e3
WORKER=t71e3 tools/wasm/with-lock.sh sh -c 'WASM_PROFILE=web tools/wasm/build-engine.sh > runs/T7.1e3/build.log 2>&1; s=$?; if [ $s -eq 0 ]; then rm -r runs/web-t71e 2>/dev/null; cp -RP upstream/binaries/system-web runs/web-t71e; fi; exit $s'; echo EXIT=$?
```
Then run the GUI check in the background (your bash tool stops commands after 900 s):
```bash
WORKER=t71e3 LOCK_NAME=mp tools/wasm/with-lock.sh sh -c 'MP_GUI=1 RELAY_PORT=20640 caffeinate -dims node tools/web/mp-check.mjs runs/web-t71e runs/T7.1e3/gui 120 8109 > runs/T7.1e3/gui.log 2>&1' & W=$!
```
Poll every 60 s with `tail -3 runs/T7.1e3/gui.log` until `PASS=` appears or `kill -0 $W` fails.
Expected `PASS=true`. Report the player names both mainlogs show (`grep -o "m_Name: [^,]*"` on
`runs/T7.1e3/gui/*.mainlog.html | sort | uniq -c`): they must be two different `Player NNNN`
names (or one `Player NNNN` + whatever the host shows). Then run the plain regression the same
background way (no `MP_GUI`, outdir `runs/T7.1e3/plain`) → `PASS=true`.
