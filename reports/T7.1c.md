## mp-check changes (short)

`tools/web/mp-check.mjs` only (`node --check` → `EXIT=0`, observed):

- Header documents `MP_NATIVE=client` (browser host, native client joins 127.0.0.1), `MP_NATIVE=host`
  (native host, browser client joins 127.0.0.1) and `MP_NATIVE_ARGS` (space-separated extra native
  args). Unset keeps today's two-browser behaviour.
- `startNative(role)` spawns `<root>/upstream/binaries/system/pyrogenesis` with `cwd` = that
  directory, `-mod=public`, the role's `-autostart*` args, then `MP_NATIVE_ARGS`. stdout+stderr are
  split line by line into `<outdir>/native.log` with `[stamp]` prefixes and into `lines`; the
  returned object is `{ name: 'native', lines, started, matchLineIndex, proc }`, sets `started` on
  `GAME STARTED` and says `native: in the match`. `cleanup()` sends `SIGKILL` if it is still running.
- Flow: `client` = host page first, wait for `host.bound`, then `startNative('client')`;
  `host` = `startNative('host')`, `sleep(15000)`, then the client page only.
- The match loop logs every browser page's stats every 30 s plus `native turn lines <n>` (native
  lines matching `/turn/i`).
- `summary.json` gets a `native` entry: `reachedMatch`, `matchStartSeconds`, `exited` (exit code or
  `null` while running), `desyncLines`, `errorLines` (first 40), plus `turnLines`; the engine's
  `~/Library/Application Support/0ad/logs/mainlog.html` is copied to `<outdir>/native.mainlog.html`
  with `copyFileSync` (missing file is ignored, never deleted).
- PASS with a native side = every browser page in the run reached the match, no desync line on it,
  its `sent` and `received` grew, it is still connected (`connected()` as before), and the native
  side reached the match, is still running at the end and has no desync line. The two-browser PASS
  rule is unchanged.
- The `host`/`client` summary keys are now created only for the pages a run actually opens (one of
  them is absent with `MP_NATIVE`); the two-browser run still writes both.
