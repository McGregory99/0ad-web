## Tunnel C API

`tools/wasm/enet-tunnel.c` — **observed** in `git diff` below, both functions are
`EMSCRIPTEN_KEEPALIVE` like the other exported ones:

1. `int zeroad_net_room_meta (int port, const char * json)` — returns -1 for `json == NULL` or
   `strlen(json) > 512` (the relay's 513-byte META limit, `tools/relay/PROTOCOL.md`). Under
   `tunnelLock` it scans the fixed socket table for a slot with `used && !failed && boundKnown &&
   bound.port == port`. **Derived**: the port was already stored, by `zeroad_net_bound`
   (`s->bound.port`, `boundKnown = 1`), so nothing new had to be stored. No such slot → -1.
   Otherwise it allocates a `TunnelCommand` with the same fields `enet_socket_send` uses
   (`type = TUNNEL_SEND_DATA`, slot, generation, port 0, `length = 1 + strlen(json)`) whose `data`
   is `0x03` followed by the JSON bytes (no NUL) and posts it with `tunnel_post`, then returns 0.
   The I/O thread's SEND_DATA branch (`enet-tunnel.pre.js`) sends `length` bytes verbatim once the
   socket is bound, which is exactly a META message.
2. `char * zeroad_net_rooms_json (void)` — an `EM_JS` (main thread) that returns
   `stringToNewUTF8(Module.zeroadNet.roomsText())`, or `stringToNewUTF8("")` when
   `Module.zeroadNet` is absent (Node build). The caller (`WebRoomList`) frees it.

`tools/wasm/enet-tunnel.pre.js`, top block (`Module.zeroadNet`): new `rooms` (the last text),
`roomsFetching`, `roomsStarted` and `roomsText()`. `roomsText()` starts a `fetch` only when none is
running and the last one started ≥ 2000 ms ago; the URL is the relay URL with `ws`→`http` /
`wss`→`https`, trailing `/` stripped, then `/rooms` (so `ws://127.0.0.1:20660/` →
`http://127.0.0.1:20660/rooms`), with `{ cache: 'no-store' }`; the text is kept only when
`response.ok`, `""` on a failed fetch, and `""` before the first answer. Header comment updated to
mention `rooms`.

One deviation, **observed**: the first version used `stringToNewUTF8 ('')` inside `EM_JS` and
`build-enet.sh` warned `enet-tunnel.c:412:33: warning: empty character constant
[-Winvalid-pp-token]`. Nothing failed to compile, but I changed it to `stringToNewUTF8 ("")` and
rebuilt; the warning is gone (`runs/T7.2b/enet.log` is now just `installed
.../wasm/deps/prefix/lib/libenet.a`).

There is no tunnel header, so the engine declares both functions itself (Step 2).

### web_roomcode.js

- New pure function `webRoomListItems(text, escape)` → `{ labels, codes }`. `""`/invalid JSON/no
  `rooms` array → both empty; rooms without an integer `code` are skipped; the rest sorted by
  `code`; label `escape(name) + " (" + code + ")"` for a non-empty string `name`, else
  `"Room " + code`; `" — " + players + " players"` appended when `players` is an integer. `codes`
  are strings, because that is what the drop-down's `list_data` holds.
- Install block (browser build only, after the relay config check):
  - `webInstallRoomList()` is called from the wrapped `init()` and installs `joinRoomList.onTick`
    and `joinRoomList.onSelectionChange`, each new `Engine.*` call guarded with
    `typeof Engine.WebRoomList === "function"` / `typeof Engine.WebRoomAnnounce === "function"`.
  - `onTick`: only while `pageJoin` is visible, at most every 2000 ms, calls
    `Engine.WebRoomList()`, and when the text changed rebuilds `list` / `list_data` with
    `webRoomListItems(text, escapeText)`. No rooms → `["(none)"]` / `[""]` / `enabled = false`;
    otherwise `enabled = true` and the previously selected code stays selected if still listed
    (first room otherwise).
  - `onSelectionChange`: if the selected `list_data` entry is a code, `joinServer.caption = code`.
  - `startHost` wrapper: after the original succeeded,
    `Engine.WebRoomAnnounce(port, JSON.stringify({ name: playername }))` and
    `warn("Room announce: " + result)`.

Two fixes I had to make to my own change (**observed** by the first GUI run, `runs/T7.2b/gui-run1`):

1. The handler was installed at script-load time and both pages logged
   `ERROR: Failed to get GUI object by name: object 'joinRoomList' not found` /
   `'pageJoin' not found` — `web_roomcode.js` is loaded by the XML's `<script>` element before the
   objects exist. Moved the install into the wrapped `init()`, which runs after the page XML is
   loaded; the errors are gone (run 4: `grep ERROR runs/T7.2b/gui/*.console.log` prints nothing).
2. The next run (`runs/T7.2b/gui-run3`) showed the drop-down label but the server field kept
   `127.0.0.1` (decoded from the screenshot, see below): after the "(none)" state, selecting the
   first room re-assigned index 0 and `CList` only fires `SelectionChange` when `selected` is set,
   so the handler never ran. Now the index is re-assigned when the room under it changed
   (`items.codes[index] !== selected`), and not on every 2 s rebuild, so a typed address is not
   overwritten.
