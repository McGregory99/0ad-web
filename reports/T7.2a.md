## Change (relay.mjs, PROTOCOL.md)

`tools/relay/relay.mjs` — **observed** in the diff below:

1. **Room range.** New options `roomMin` / `roomMax` from `options.roomMin` / `options.roomMax`,
   then `RELAY_ROOM_MIN` / `RELAY_ROOM_MAX`, defaults 20700 / 20999. Both env vars are documented
   in the header comment. A session becomes a room when its bound UDP port is in
   `roomMin..roomMax`, inclusive: on BOUND the relay stores
   `{ code: udpPort, name: null, players: null, since: Date.now() }` in a `Map` keyed by the UDP
   port.
2. **`META = 0x03`** exported next to the other types. Layout `[0x03][utf-8 JSON]`, at most 513
   bytes (`MAX_META`, also exported). Before BOUND the existing "first message must be BIND" rule
   still applies (META → ERROR + close). After BOUND, META is dropped (`stats.dropped++`, session
   stays open) when the session is not a room, when the message is longer than 513 bytes, when
   the text is not valid JSON, or when the JSON is not a plain object (arrays and `null` rejected).
   Otherwise `name` and `players` are stored, replacing any earlier META:
   - `name`: strings have U+0000..U+001F and U+007F removed, are trimmed, then cut to the first 40
     characters with `Array.from(...).slice(0, 40).join('')`; empty or non-string → `null`.
   - `players`: `Number.isInteger(players) && 0 <= players <= 64` → the number, else `null`.
   - Every other field is ignored. META while the UDP socket is binding is dropped by the existing
     `binding` rule.
3. **HTTP `GET /rooms`** via `server.on('request', ...)` on the same server as the WebSocket
   upgrades (the `ws` server keeps handling `upgrade`, so WS connections still work — the old WS
   tests pass unchanged). Response 200 with
   `{"rooms":[{"code":…,"name":…,"players":…,"age":…}]}`, one entry per open room session, sorted
   by `code` ascending, `name`/`players` `null` until a META arrives, `age = Math.floor((now - since)/1000)`.
   Headers: `Content-Type: application/json`, `Cache-Control: no-store`,
   `Access-Control-Allow-Origin: *`, `Cross-Origin-Resource-Policy: cross-origin`.
   The query string is ignored (path is parsed with `new URL(...).pathname`), any other path is
   404 with plain-text body `not found`, any other method on `/rooms` is 405 with `Allow: GET`.
   A closed session leaves the list at once: `rooms.delete(udpPort)` sits next to
   `boundPorts.delete(udpPort)` in the session `close()`.

## Tests (names, three runs with counts)

All tests are in `tools/relay/relay.test.mjs`; the 10 pre-existing tests are unchanged. The 7 new
tests use the global `fetch`, take a free UDP port `P` (bind a `dgram` socket to port 0, read the
port, close it) and start a separate relay with `{ port: 0, roomMin: P, roomMax: P, log: () => {} }`,
closed at the end of each test, then `BIND P`.

New tests (**observed** names from the run log):
- `GET /rooms on a relay with no sessions is an empty list with the CORS/CORP headers`
- `a room session is listed, META fills name and players, closing removes it`
- `a session bound outside the room range is not listed and its META is dropped`
- `a room drops invalid META without closing and keeps the last valid name`
- `META cleans the name and validates players`
- `META as the very first message is an error and closes the WebSocket`
- `HTTP: unknown paths 404, other methods on /rooms 405, query string ignored`
