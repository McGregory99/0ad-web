# Runbook T7.1x — Relay errors reach ENet; relay bind race (worker t71x)

Read `runbooks/_wave7-common.md` first. Report: `reports/T7.1x.md`. Logs: `runs/T7.1x/`.

## Background (supervisor)

The browser build sends every ENet socket through a WebSocket to the UDP relay
(`tools/relay/PROTOCOL.md`). Two defects were found in review:

1. **A relay ERROR is invisible to ENet.** When the relay cannot bind the requested UDP port
   (e.g. 20595 already in use) it sends `ERROR` and closes the WebSocket. The page only logs it
   (`tools/wasm/enet-tunnel.pre.js`, `onMessage`, `bytes[0] === ERROR`). The C side
   (`tools/wasm/enet-tunnel.c`) keeps answering `enet_socket_send` with "sent" and
   `enet_socket_receive` with "nothing yet", so a host looks like it is hosting but nobody can
   reach it. Wanted: after an ERROR, or after the relay closes the WebSocket on its own, the
   socket is marked failed and `enet_socket_send` / `enet_socket_receive` return `-1`.
   (The game server then logs `CNetServerWorker: enet_host_service failed (-1)`,
   `upstream/source/network/NetServer.cpp:495-500`, which the player sees as an error line.)
2. **Relay bind race.** In `tools/relay/relay.mjs`, `udp` is assigned before
   `await bindUdp(...)`. If the WebSocket closes while the bind is pending, `close()` calls
   `udp.close()` on a socket that is still binding and deletes port 0 from `boundPorts`, and then
   the code after the `await` calls `udp.close()` a second time (Node throws
   `ERR_SOCKET_DGRAM_NOT_RUNNING` inside an async handler). Wanted: no double close, no crash,
   the UDP socket is always closed exactly once.

## Step 2 — Relay fix (GREEN)
In `relay.mjs`, inside `ws.on('message', ...)`, bind into a local variable and only assign
`udp` after the bind succeeded and the session is still open:
```js
const socket = dgram.createSocket('udp4');
binding = true;
try {
	udpPort = await bindUdp(socket, wanted);
} catch (error) {
	socket.close();
	binding = false;
	return closed ? undefined : fail(`bind ${wanted}: ${error.code ?? error.message}`);
}
binding = false;
if (closed) { socket.close(); return; }
udp = socket;
```
Declare `let binding = false;` next to `let udp = null, ...`, and while `binding` is true ignore
further messages (`if (binding) { stats.dropped++; return; }` at the top of the handler, after the
`lastActive` update). The first-message check stays `if (!udp)`. Run all relay tests:
`node --test tools/relay/relay.test.mjs > runs/T7.1x/relay-green.log 2>&1; echo EXIT=$?; tail -20 runs/T7.1x/relay-green.log`
Expected: EXIT=0, all tests pass (there were 9 before your test).

## Step 3 — Failed sockets in the tunnel (C)
In `tools/wasm/enet-tunnel.c`:
1. Add `int failed;` to `TunnelSocket` (after `boundKnown`), with a comment
   `/* the relay refused or closed this socket: send and receive fail */`.
   Make sure the place that (re)initialises a slot when a socket is created sets it to 0
   (find where `boundKnown` is reset or the slot is cleared, and do the same).
2. Add, next to `zeroad_net_bound`, an exported function:
```c
/* The relay sent ERROR or closed the WebSocket on its own. Later sends and receives fail. */
EMSCRIPTEN_KEEPALIVE void
zeroad_net_failed (int slot, int generation)
{
    TunnelSocket * s;
    pthread_mutex_lock (& tunnelLock);
    s = tunnel_get (slot);
    if (s != NULL && s -> generation == generation)
      s -> failed = 1;
    pthread_mutex_unlock (& tunnelLock);
    pthread_cond_broadcast (& tunnelArrived);
}
```
3. `enet_socket_send`: where it reads `valid` and `generation` under the lock, also treat a
   failed socket as invalid (return -1).
4. `enet_socket_receive`: after the lock section, if the socket exists, is failed and there is
   no queued frame, return -1 (frames that arrived before the failure are still delivered first).
5. `enet_socket_wait` / `enet_socketset_select`: if they loop until a frame arrives, make a
   failed socket count as "readable" so the caller's next receive returns -1 right away.
   If the structure makes this unclear, skip this item and say so in the report.
Keep the file's style (spaces before parentheses, `->` with spaces).

## Step 4 — Failed sockets in the page (JS)
In `tools/wasm/enet-tunnel.pre.js`:

- in `s.ws.onclose`, inside the existing `if (!s.closed)` case (closed by the relay, not by the
