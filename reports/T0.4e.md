Notes on the implementation:
- The snapshot flag is reset in **all three** places where `turnCache` is replaced: the
  non-cacheable branch of `rpcCached`, `gamestateInit` and `compute`. **(observed)**
- Cache keys are built with the same shape and property order as the real calls
  (`{ op, ent, iid }` and `{ op, ent, iid, method, args: [] }`), so the Proxy-generated keys hit.
  **(derived from reading the Proxy in `ai-worker.js` and `Codec.encode` = `JSON.stringify`)**
- Entities absent from the snapshot are not cached by `takeSnapshot`, so they fall through to the
  normal `rpc`; a snapshot never answers `false`. **(observed in the code above)**
- `stats.snapshots` is counted per request and appended as a 7th column of the stats line; existing
  readers use columns 1–6, so the format stays compatible. **(derived)**

### What the numbers say (derived)

- The five targeted keys cost **25,559.6 ms** before and **31,323.7 ms** after
  (snapshot 28,925.9 + `qi:90` 2,365.9 + `qi:89` 31.9). That is **+22.6%**: the snapshot is more
  expensive than the queries it replaces.
- Mean snapshot cost: 28,925.9 ms / 5,415 = **5.34 ms** per snapshot. 5,415 snapshots over 12,420
  computations = 0.436 per computation.
- The callback count fell 12.5× (1,068,810 → 85,272), so the per-call overhead is gone, but the bulk
  fetch is dominated by the data volume: each snapshot walks every entity carrying the interface,
  calls `QueryInterface` plus one or two getters on each, and round-trips the whole table through the
  JSON codec. That cost is paid even when the computation only asks about a handful of entities
  (9,436 of 12,420 computations take no snapshot at all, and 552 take one).
- `qi:90` still makes 69,961 engine calls: entities **without** iid 90 are absent from the snapshot
  and fall through to the real rpc, as required by the runbook ("never answer `false`"). Those
  negative lookups were 16% of the old `qi:90` calls and cannot be served by this snapshot design.
- The final state hash is unchanged by the optimisation and still differs from the native reference
  `6908836f8d8ca50562faab971ad0c4ca` (the same discrepancy T0.4c already flagged; it is not caused by
  this change). **(observed)**

## Attempt 1 (rejected, kept for the record)

The first build+replay also returned EXIT=0 and AICMP EXIT=0, but the worker never started:

```
569.9	ERROR: JavaScript error: (eval) line 131
570.1	expected expression, got ')'
570.3	ERROR: AI worker: failed to set up the remote AI helper; running the AI in-process
```

Cause **(observed)**: I inserted the `snapshot` block immediately before the `}` that closes the
`switch`, and used that brace as the block's own closing brace, so the `switch` was left unclosed and
`AI_REMOTE_HELPER_JS` became invalid. The fix was to add the missing `}` (now line 297); no other
change was needed. I confirmed it by extracting the helper JS from the C++ raw string and running
`node --check`, and by diffing against `patches/upstream/0019-emscripten-remote-ai.patch`.

That attempt is **not** the reported result: with the remote helper disabled the engine fell back to
the in-process AI, so no `runs/T0.4e.worker` file was produced (`ls` → No such file or directory),
the replay took 244.7 s, and the final state was `6908836f8d8ca50562faab971ad0c4ca` — the native
reference value, which is exactly what an in-process run produces. The reported run is the second
one, where the worker ran.

## Caveats

- T0.4c was measured on 2026-11-07 at 15:41 and T0.4e on 2026-11-08 at 10:47, on a machine shared
  with five other workers (builds and replays active at 10:28–10:35). Wall-clock deltas of a few
  percent would be noise; the +22.8% wall time and the per-key ms figures agree, so the regression is
  real **(derived)**.
- `simcall:Sim.RequirementsHelper.AreRequirementsMet` costs 474.6 ms before and 1,003.5 ms after with
  the identical 9,101 calls **(observed)**. Nothing in this change touches that path; I attribute it
  to machine load, not to the snapshot **(inferred)**.
- The runbook's Step 1 snippet ends with a single `}` that closes the `case` block; the existing `}`
  that closes the `switch` must be kept. Anyone repeating this must add both.
