## Observations for the supervisor (no fixes attempted, nothing edited)
- **Observed:** Step 1 built both variants cleanly (both EXIT=0) with identical flags except `-sPROXY_TO_PTHREAD=1 -sOFFSCREENCANVAS_SUPPORT=1` on the pthread build.
- **Observed:** the main-thread variant runs the WebGL2 loop in headless Chrome at ~60 FPS.
- **Observed:** the pthread variant never reaches the GL code: the page fails immediately with `InvalidStateError: ... Cannot get context from a canvas that has transferred its control to offscreen` at `index.js:1`. This is thrown while the main thread tries `getContext` on a canvas that was already transferred to the offscreen canvas (the pthread build enables `-sOFFSCREENCANVAS_SUPPORT=1` and proxies to a pthread).
- **Derived:** because the pthread variant dies during startup, there is no `GL_VERSION`, no `FPS`, and no `main_browser_thread=0` line — the expected `main_browser_thread=0` for that variant was never printed.
- **Inferred (guess, not verified):** `main.c` most likely calls `SDL_GetWindowSurface`/`getContext` on the DOM canvas after Emscripten has transferred control to the offscreen canvas, so the spike needs either a different canvas-access path or dropping `OFFSCREENCANVAS_SUPPORT`; this was **not** investigated further and `main.c`/`serve.mjs` were not edited.
