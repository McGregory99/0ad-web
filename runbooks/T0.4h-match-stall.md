# Runbook T0.4h — Does the mid-match stall reproduce, and is it PBL? (worker t04h)

Read `runbooks/_wave7-common.md` first. Report: `reports/T0.4h.md`. Logs: `runs/T0.4h/`.
Port: http 8113 (t04g is finished). Measurement only: change no code.

## Background (supervisor)
T0.4g (`reports/T0.4g.md`) ran a skirmish in Chrome (GPU) with 30 `fps:60` windows. Windows 1-4
were 60 fps, then the page console stopped for 30 minutes after
`[345.0] log: [zeroad] IDBFS persist 2657 ms` (earlier persists took 2-13 ms) and the run had to be
killed. Since then PBL is on by default (`?pbl=0` turns it off). We need to know whether the
stall reproduces, and whether it depends on PBL.

## Files you may edit
- new: `runs/T0.4h/*` only.

## Step 1 — Two runs, one after the other (about 15 minutes each)
Run A (default, PBL on) and then run B (`pbl=0`), each with 12 windows. Use the same command
shape as T0.4g; the query of run B adds `pbl=0&`. Your bash tool stops commands after 900 s,
so start each in the background with `nohup` (as you did in T0.4g, `runs/T0.4g/run.sh`) and poll
every 120 s with `grep -c '] fps ' runs/T0.4h/<run>/console.log; tail -2 runs/T0.4h/<run>/console.log`.
```bash
mkdir -p runs/T0.4h
W=$(for i in $(seq 12); do printf 'fps:60,'; done)
S="wait:25,shot:menu,click:491:553,wait:2,click:180:221,wait:3,click:418:221,wait:8,click:1185:681,wait:40,shot:start,${W}stats,shot:end"
# run A
CHROME_GPU=1 caffeinate -dims node tools/web/chrome-shot.mjs runs/web-t72b runs/T0.4h/a "$S" '?arg=-mod=public&arg=-conf=windowed:true' 8113 > runs/T0.4h/a.log 2>&1; echo EXIT=$? >> runs/T0.4h/a.log
# run B
CHROME_GPU=1 caffeinate -dims node tools/web/chrome-shot.mjs runs/web-t72b runs/T0.4h/b "$S" '?pbl=0&arg=-mod=public&arg=-conf=windowed:true' 8113 > runs/T0.4h/b.log 2>&1; echo EXIT=$? >> runs/T0.4h/b.log
```
A run is **stalled** when its console gets no new line for 5 minutes. Then: record the time of
the last line, `ps -Ao pid,pcpu,rss,comm | grep -i chrom | sort -k2 -nr | head -5` (CPU of the
Chrome processes while stalled), take `uptime`, then kill only that run's node process by PID and
go on to the next run. Never use `pkill`/`killall`.

## Step 2 — Report
For each run: EXIT, number of fps windows, the fps lines, the last 8 console lines, every

Compare A and B in one short table. Do not guess a fix.
