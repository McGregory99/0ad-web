# Runbook T4.5b — mp-check can test a deployed site (worker t45b)

Read `runbooks/_wave7-common.md` first. Report: `reports/T4.5b.md`. Logs: `runs/T4.5b/`.
Ports: http 8111 (yours only), relay 20650 (yours only).

## Background (supervisor)
`tools/web/chrome-shot.mjs` already has `SITE_URL` (read how it is done there: env read, query
joined after exactly one `/`, no local server, `--ignore-certificate-errors`, `site url:` line).
Now `tools/web/mp-check.mjs` needs the same, so its two pages (and `MP_GUI=1`) can run against a
deployed site whose page and relay are both remote. Today mp-check always spawns the relay
(line ~55) and `serve.mjs` (line ~62), and every `Page.navigate` uses
`http://127.0.0.1:${port}/...` (lines ~295-356); `base` (line ~263) adds `&relay=ws://127.0.0.1:...`.

## Files you may edit
- `tools/web/mp-check.mjs`
- new: `runs/T4.5b/*`

## Step 1 — `SITE_URL` env
When `process.env.SITE_URL` is set and non-empty:
- do NOT spawn the relay nor `serve.mjs`; guard every later use (kill, stdout/stderr handlers,
  relay log copy) so nothing breaks when they are null;
- `base` has NO `&relay=...` part (the page then uses its default relay, `wss://<page host>:20600/`);
- every `Page.navigate` URL becomes `<SITE_URL without trailing slashes>/<query>`: write ONE
  helper `pageUrl(query)` and use it in all navigate calls (with SITE_URL unset it returns the
  old `http://127.0.0.1:${port}/${query}`);
- add `--ignore-certificate-errors` to Chrome's arguments;
- `say()` one line `site url: <SITE_URL>` at start;
- `MP_NATIVE` with `SITE_URL` is not supported: exit 2 with a clear message.
Update the header comment (one line). With SITE_URL unset, behaviour must be unchanged.
`node --check tools/web/mp-check.mjs` → exit 0.

## Step 2 — Tests (build `runs/web-t71e`, read-only)
Run both in the background (your bash tool stops commands after 900 s) and poll every 60 s with
`tail -3 <log>` until `PASS=` appears or the process ended.
a) Regression, no SITE_URL:
```bash
mkdir -p runs/T4.5b
WORKER=t45b LOCK_NAME=mp tools/wasm/with-lock.sh sh -c 'RELAY_PORT=20650 caffeinate -dims node tools/web/mp-check.mjs runs/web-t71e runs/T4.5b/plain 60 8111 > runs/T4.5b/plain.log 2>&1' & W=$!
```
b) SITE_URL against a local server + relay you start yourself, relay on port 20600 is NOT
allowed here (other workers), so for this test only pass the relay explicitly: start
`RELAY_HOST=127.0.0.1 RELAY_PORT=20650 node tools/relay/relay.mjs > runs/T4.5b/relay.log 2>&1 &`
and `node tools/spikes/serve.mjs runs/web-t71e 8111 > runs/T4.5b/serve.log 2>&1 &`, then
```bash
WORKER=t45b LOCK_NAME=mp tools/wasm/with-lock.sh sh -c 'SITE_URL="http://127.0.0.1:8111/" SITE_RELAY="ws://127.0.0.1:20650/" caffeinate -dims node tools/web/mp-check.mjs runs/web-t71e runs/T4.5b/url 60 8199 > runs/T4.5b/url.log 2>&1' & W=$!
```
For this, also support an optional env `SITE_RELAY`: when set together with SITE_URL, `base`
gets `&relay=<encoded SITE_RELAY>` again. Kill the relay and server you started by their PIDs
afterwards (never `pkill`/`killall`).
Expected: both `PASS=true`; `url.log` has the `site url:` line; nothing listened on 8199 or
started a relay from mp-check in (b) (say how you checked).
