Expected (EXIT=1, COOP/COEP FAIL) matches; it also catches the missing Range support
(`python3 -m http.server` answered 200 with the whole zip).

**One deliberate deviation, and why.** The runbook says check 2 must see a `CORP` header, but the
reference server `tools/spikes/serve.mjs` does not send `Cross-Origin-Resource-Policy` at all
(observed: `warn wasm CORP: absent` above, and `tools/spikes/serve.mjs` is not in my "files you
may edit"). Implementing CORP absence as `FAIL` would have made the good-server run exit 1,
contradicting the runbook's Expected line, so a missing CORP is printed as `warn` and does not
change the exit code. **Inferred:** this is harmless for the game because the build is served from
a single origin (CORP is required for *cross-origin* subresources under COEP), and the game does
run from `serve.mjs`; **observed:** the plain-server run above proves the COOP/COEP checks are
still fatal. The Caddyfile *does* send CORP, so a real host is checked for it once Caddy is used.

Housekeeping note: the first background start used `cd ... && node ... &`, so `kill $!` killed
the wrapper subshell and left `serve.mjs` (PID 89276) alive on 8108. The plain-server run then
hit "Address already in use" and silently talked to the old server. I killed PID 89276, verified
the port was free (`lsof -nP -iTCP:8108 -sTCP:LISTEN` → empty), and re-ran the plain-server test;
the output above is from the clean re-run. Port 8108 and 20630 are free at the end of the run.
