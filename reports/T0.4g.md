### The hang (observed)

`runs/T0.4g/match/console.log` reached 2971 bytes / 56 lines at local 23:25:06 and was **not
modified again until I killed the run at 23:55** (**observed** `ls -l`, byte size identical on
every 120 s poll from 22:27 to 22:55). Its last lines (**observed** `tail -4`):
```
[320.1] fps {"frames":3600,"fps":60,"p50":16.7,"p99":16.7,"max":33.3}
[321.6] log: [zeroad] IDBFS persist 10 ms
[331.6] log: [zeroad] IDBFS persist 2 ms
[345.0] log: [zeroad] IDBFS persist 2657 ms
```
The game's own 10 s `[zeroad] IDBFS persist` log line, which had fired reliably every ~10 s up to
that point, stopped too — so JS timers/rAF in the page stopped, not just my `fps` step. While it
was stuck, the Chrome renderer processes were still burning CPU (**observed** `ps aux`, three
samples): pid 2438 at 26.1 % → 33.8 % → 44.7 %, pid 2426 at 18.0 % → 15.2 % → 20.3 %. So the
renderer was busy but produced no console output for 30 minutes (**derived**).

I did not retry: the runbook allows a retry only for obviously transient errors, and a renderer
that hangs mid-match with a busy main thread is not obviously transient. I killed the run so the
machine is not left with a CPU-burning Chrome (**observed**: after `kill 2400 2399`,
`pgrep -f chrome-shot.mjs` finds nothing and 0 "Google Chrome for Testing" processes remain).
