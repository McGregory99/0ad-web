# Runbook T0.4e — One resource snapshot per AI computation (worker t02, Node only)

Read `runbooks/_wave5-common.md` first. Report: `reports/T0.4e.md`.

Context (your T0.4c/T0.4d reports): the remote AI spends most callback time on per-entity pairs
`qi(ent, 90)` + `qicall(ent, 90, GetCurrentAmount|GetNumGatherers)` and `qi(ent, 89)` +
`qicall(ent, 89, GetCarryingStatus)`. The simulation does not change while the AI computes, and the
worker already caches read-only results for one computation (`turnCache` in
`tools/wasm/ai/ai-worker.js`, `rpcCached`).

Goal: when the worker first needs one of those values in a computation, fetch ALL of them in ONE
request, and fill `turnCache` with exactly the keys the single calls would have used. Petra code
does not change. The AI commands must stay byte-identical (aicmp EXIT=0).

Allowed edits: `tools/wasm/ai/ai-worker.js`, and the JS text of `run(request)` inside
`upstream/source/simulation2/components/CCmpAIManager.cpp` (around line 266). Nothing else.

## Step 1 — Engine side: add a `snapshot` op
In `run(request)` in CCmpAIManager.cpp add:
```js
	case 'snapshot': {
		// { iid, methods: [names] } -> [[ent, [value per method]], ...] for every entity with iid
		const out = [];
		for (const ent of SimEngine.GetEntitiesWithInterface(request.iid)) {
			const cmp = SimEngine.QueryInterface(ent, request.iid);
			out.push([ent, request.methods.map((m) => cmp[m]())]);
		}
		return out;
	}
```
First check that `SimEngine.GetEntitiesWithInterface` exists in that realm:
`grep -n 'SimEngine' upstream/source/simulation2/components/CCmpAIManager.cpp | head` and
`grep -rn 'GetEntitiesWithInterface' upstream/source/simulation2/scripting/*.cpp | head`.
If it has another name, use that name and write it in the report. Do not add C++ functions.

## Step 2 — Worker side
In `ai-worker.js`:
1. A table of what to prefetch: `{ 90: ['GetCurrentAmount', 'GetNumGatherers'], 89: ['GetCarryingStatus'] }`.
   Confirm the exact method names and iids from your T0.4c `.keys.json` file.
2. A per-computation flag per iid, reset whenever `turnCache` is replaced (both places: the
   non-cacheable branch of `rpcCached`, and the start of each computation — find where `turnCache`
   is reset per computation).
3. Before a cached lookup of `qi` or `qicall` for iid 89/90: if that iid's snapshot was not taken
   since the last reset, send ONE `rpc({ op: 'snapshot', iid, methods })`, then for every
   `[ent, values]` put into `turnCache`:
   - the key of the `qi` request for (ent, iid) → `true`
   - the key of each `qicall` request for (ent, iid, method, args: []) → the value.
   Build those keys with the SAME object shape and property order the real calls use
   (`Codec.encode({ op: 'qicall', ent, iid, method, args })` — copy the shape from line ~301).
4. Entities not in the snapshot fall through to the normal rpc. Never answer `false` from the snapshot.
5. Count snapshots in `stats` (e.g. `stats.snapshots`).

WORKER=t02 tools/wasm/with-lock.sh sh -c 'WASM_PROFILE=node tools/wasm/build-engine.sh > runs/T0.4e-build.log 2>&1 && tools/bench/ai-replay.sh T0.4e ZEROAD_AI_REMOTE=1 ZEROAD_AI_LOG=$PWD/runs/T0.4e.ailog ZEROAD_AI_WORKER_STATS=$PWD/runs/T0.4e.worker > runs/T0.4e-replay.log 2>&1'; echo "EXIT=$?"

Expected: EXIT=0 and AICMP EXIT=0. If AICMP is not 0, find the first differing turn, fix, and repeat (max 3 tries).
Then compare against T0.4c: total callbacks, callback ms, top 10 keys by ms from the two
`.keys.json` files, and replay wall time.
