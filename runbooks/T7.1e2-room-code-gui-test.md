## Step 1 — `MP_GUI=1` mode in mp-check
Read how `tools/web/chrome-shot.mjs` sends clicks and keys over CDP (`Input.dispatchMouseEvent`,
`Input.dispatchKeyEvent`) and copy that logic into mp-check as `page.click(x, y)` and
`page.key(key)` (DOM key names, including `Backspace` and single characters).
With env `MP_GUI=1` (two browser pages, no autostart arguments in either query):
1. Open the host page (base query only). Wait 25 s. Click `491:553`, wait 2 s, `180:253`,
   wait 2 s, `418:317`, wait 3 s, `748:453` (Continuar).
2. Wait (max 60 s) for a host console line matching `/Room code: (\d+)/`; that number is CODE.
   `say()` it and store it in the summary. No line → fail.
3. Open the client page (base query). Wait 25 s. Click `491:553`, `180:253`, `418:285`
   (2-3 s apart). Click the server field `748:339`, press `End`, press `Backspace` 20 times,
   type CODE digit by digit with `page.key`, click `748:473` (Continuar).
4. Wait 20 s (the client joins the host's game setup), then on the host click `1185:681`.
5. From here the existing flow applies: wait for both `GAME STARTED`, stay `matchSeconds`,
   same stats, same PASS rule (`summary.roomCode` = CODE).
Take a screenshot of each page after steps 1, 3 and 4 (`<outdir>/<page>-step<N>.png`) — the
supervisor will look at them if it fails. `node --check tools/web/mp-check.mjs` → 0.

## Step 2 — Run it
```bash
mkdir -p runs/T7.1e2
WORKER=t71e LOCK_NAME=mp tools/wasm/with-lock.sh sh -c 'MP_GUI=1 RELAY_PORT=20640 caffeinate -dims node tools/web/mp-check.mjs runs/web-t71e runs/T7.1e2/gui 120 8109 > runs/T7.1e2/gui.log 2>&1' & W=$!
```
Your bash tool stops commands after 900 s, so it runs in the background: poll every 60 s with
`tail -3 runs/T7.1e2/gui.log` until a `PASS=` line appears or `kill -0 $W` fails.
Expected: `PASS=true` and a `Room code:` line. If it fails, report the step it reached, the
last 20 lines of both console logs, and list the step PNGs. Do not change engine or GUI code.
