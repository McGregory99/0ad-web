# T4.5b — SITE_URL in mp-check
STATUS: done

## Change (diff summary)

Edited `tools/web/mp-check.mjs` only.

- New env reads: `SITE_URL` and optional `SITE_RELAY` (both trimmed); `siteBase` = `SITE_URL` with
  trailing slashes removed; one helper `pageUrl(query)` returns `siteBase + '/' + query` when
  `SITE_URL` is set and the old `http://127.0.0.1:${port}/${query}` otherwise. All four
  `Page.navigate` call sites (MP_GUI host, MP_GUI client, MP_NATIVE=host client, default host and
  client) and their `say()` lines now use `pageUrl(...)`. **observed** in the diff above.
- With `SITE_URL` set: `relayLog`, `relay` and `server` are `null`; the relay spawn + its
  stdout/stderr piping + its `exit` handler are guarded by `if (relay)`, `serve.mjs` is not spawned,
  and `cleanup()` guards `if (server)` / `if (relay)` before killing. **observed** in the diff.
- `say(`site url: ${siteBase}`)` one line right after the log file is initialised. **observed**
  (`url.log` line 1).
- Chrome gets `--ignore-certificate-errors` only when `SITE_URL` is set. **observed** in the diff.
- `base`: with `SITE_URL` there is no `&relay=...` part, unless `SITE_RELAY` is also set, in which
  case `base` gets `&relay=<encoded SITE_RELAY>`; without `SITE_URL` the old
  `&relay=ws://127.0.0.1:${RELAY_PORT}/` is unchanged. **observed** in the diff.
- `SITE_URL` + `MP_NATIVE` exits 2 with
  `SITE_URL and MP_NATIVE cannot be combined: a native pyrogenesis needs the local relay on UDP 20595`.
  **observed** in the diff; not exercised by a test (the runbook's Step 2 does not ask for it) —
  **inferred** that it works, from the code path.
- Header comment extended by three lines documenting `SITE_URL` / `SITE_RELAY` / the MP_NATIVE
  restriction. **observed**.
- `node --check tools/web/mp-check.mjs` → exit 0. **observed** (`exit=0`).
