## Background (supervisor)
The user accepted a new quality rule (S8-Q2a in `odd/tasks/0ad-web.md`): in a 30-minute
skirmish against Petra in Chrome (GPU, default page settings: PBL on, AI in the Web Worker),
measured in 30 one-minute windows: mean fps >= 58, every window >= 50 fps, window p99 frame
<= 50 ms in at least 28 of 30 windows, worst frame <= 500 ms.
`tools/web/chrome-shot.mjs` has a step `fps:<s>` that prints one line per window:
`fps {"frames":..,"fps":..,"p50":..,"p99":..,"max":..}` (ms). Build: `runs/web-t72b`
(read-only, current code). The START clicks are the ones from the e2e scenario.

## Step 1 — Run (about 33 minutes)
Do not run anything else heavy meanwhile. Build the scenario string with 30 `fps:60` steps:
```bash
mkdir -p runs/T0.4g
W=$(for i in $(seq 30); do printf 'fps:60,'; done)
S="wait:25,shot:menu,click:491:553,wait:2,click:180:221,wait:3,click:418:221,wait:8,click:1185:681,wait:40,shot:start,${W}stats,shot:end"
echo "$S" > runs/T0.4g/scenario.txt
(CHROME_GPU=1 caffeinate -dims node tools/web/chrome-shot.mjs runs/web-t72b runs/T0.4g/match "$S" '?arg=-mod=public&arg=-conf=windowed:true' 8113 > runs/T0.4g/match.log 2>&1; echo EXIT=$? >> runs/T0.4g/match.log) & W2=$!
```
Your bash tool stops commands after 900 s: poll every 120 s with
`grep -c '] fps ' runs/T0.4g/match/console.log; tail -1 runs/T0.4g/match.log` until `EXIT=` appears
or `kill -0 $W2` fails. If `chrome-shot.mjs` rejects the scenario (for example a step limit),
report the exact error and STOP (STATUS: blocked).
