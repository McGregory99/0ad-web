# Runbook T4.1 — Zip manifest for streaming the game data

Goal: the browser will download single files out of `public.zip` with HTTP Range
requests. For that it needs a manifest that says, for every file in the zip, at
which byte its compressed data starts and how long it is. You write a small
Python script, its tests, and run it on the real data.

- Root: `~/DEVELOPMENT/0ad-web` (ROOT)
- Files you create (ONLY these):
  - `ROOT/tools/data/make_manifest.py`
  - `ROOT/tools/data/test_make_manifest.py`
  - `ROOT/web-data/` (output folder, not committed)
- Report: `ROOT/reports/T4.1.md`
- Python: use the standard library only. Always run Python with `python3 -I`.

## Specification of `make_manifest.py`

Command line:

```
python3 -I tools/data/make_manifest.py <input.zip> <output.json> [--verify N]
```

1. Open the zip with `zipfile.ZipFile`. Skip directory entries (names ending in `/`).
2. For every file entry `info`:
   - Open the raw zip file in binary mode, `seek(info.header_offset)`, read 30 bytes.
   - Unpack with `struct.unpack('<IHHHHHIIIHH', header)`. Field 0 must be `0x04034b50`,
     otherwise raise `ValueError(f"bad local header for {info.filename}")`.
   - Field 9 is the file name length `n`, field 10 is the extra field length `m`
     (take them from THIS local header, not from `info.extra`).
   - `data_offset = info.header_offset + 30 + n + m`.
3. Each manifest entry is a dict with exactly these keys:
   `path` (str, `info.filename`), `offset` (int, data_offset), `csize` (int,
   `info.compress_size`), `usize` (int, `info.file_size`), `method` (int,
   `info.compress_type`, 0 = stored, 8 = deflate), `crc32` (int, `info.CRC`).
4. Output JSON: `{"archive": <basename of input>, "archive_size": <bytes>, "entry_count": <int>, "entries": [...]}`
   with entries sorted by `path`. Write with `json.dump(obj, f, separators=(",", ":"))`.
5. `--verify N`: after writing, pick N entries with `random.Random(0).sample(...)`
   (or all entries if fewer than N), and for each one read `csize` bytes at `offset`,
   decompress (method 0: as is; method 8: `zlib.decompress(data, -15)`), check
   `len == usize` and `zlib.crc32(data) == crc32`. Print `VERIFY OK <count>` or raise
   `ValueError` naming the first failing path. Any other method: raise `ValueError`.
6. Print one final line: `MANIFEST <entry_count> entries -> <output path>`.

## Tests (`test_make_manifest.py`, `unittest`)

Write these three tests. Each creates its zip inside `tempfile.TemporaryDirectory()`.

1. `test_stored_and_deflated_roundtrip`: zip with `a.txt` (stored, `b"hello"`) and
   `dir/b.bin` (deflated, `bytes(range(256)) * 50`). Run the script's main function,
   load the JSON, check `entry_count == 2`, the paths sorted, and for each entry read
   bytes at `offset`/`csize`, decompress, and compare to the original bytes.
2. `test_directories_skipped`: zip with an explicit directory entry `d/` and file
   `d/x.txt`; manifest must contain only `d/x.txt`.
3. `test_verify_detects_corruption`: build a valid zip, make the manifest, then
   overwrite the first byte of a deflated entry's data with a different value and
   check that the verify function raises `ValueError`.

Structure the script so tests can call it: put the logic in
`build_manifest(zip_path) -> dict`, `verify(zip_path, manifest, n) -> int`,
and `main(argv) -> int`, with `if __name__ == "__main__": sys.exit(main(sys.argv[1:]))`.
