# Runbook T0.2-E2c — Link with the supervisor's wasi compatibility shim and run in Node

E2b left 3 symbols (`_CLOCK_MONOTONIC`, `errno`, `arc4random_buf`): wasi-libc names that
Emscripten's libc lacks. The supervisor wrote `ROOT/tools/smoke/wasi_compat.c`, which defines
them and wraps `clock_gettime` (linker flag `-Wl,--wrap=clock_gettime`).

- Root: `~/DEVELOPMENT/0ad-web` (ROOT). You may create ONLY files under `ROOT/wasm/e2/`
- Report: append `## E2c` to `ROOT/reports/T0.2-E2.md`

Every shell you open must start with:

```bash
source ~/DEVELOPMENT/0ad-web/tools/emsdk/emsdk_env.sh > /dev/null 2>&1
R=~/DEVELOPMENT/0ad-web
O=$R/wasm/spidermonkey/mozjs-128.13.0/obj-wasi
cd $R/wasm/e2
```

## Step 1 — Link

```bash
em++ -std=c++20 -O2 -I$O/dist/include $R/tools/smoke/js_hello.cpp $R/tools/smoke/wasi_compat.c \
  $O/js/src/build/libjs_static.a libmozglue_extra.a $O/wasm32-wasi/release/libjsrust.a $R/wasm/deps/wasi-prefix/lib/libz.a \
  -Wl,--wrap=clock_gettime -sSTACK_SIZE=8MB -sINITIAL_MEMORY=256MB -sALLOW_MEMORY_GROWTH=1 -Wl,--error-limit=0 \
  -o js_hello.js > $R/runs/T0.2-E2c-link.log 2>&1; echo "EXIT=$?"
grep -E 'error|warning' $R/runs/T0.2-E2c-link.log | head -30
ls -la js_hello.js js_hello.wasm
```

Note: `em++` compiles the `.c` file as C++ and may warn about that; a warning is fine.
If you get an error that says the `.c` file is treated as C++ and fails, compile it first:
`emcc -O2 -c $R/tools/smoke/wasi_compat.c -o wasi_compat.o` and use `wasi_compat.o` instead.

## Step 2 — Run in Node (only if Step 1 produced `js_hello.wasm`)

```bash
cd $R/wasm/e2
( time node js_hello.js ) > $R/runs/T0.2-E2c-run.log 2>&1; echo "EXIT=$?"
tail -n 30 $R/runs/T0.2-E2c-run.log
```

Expected: `JS OK 7,<number>` and EXIT=0.

## Step 3 — Same JavaScript in native Node, for comparison

```bash
( time node -e 'let s = 0; for (let i = 0; i < 1000000; i++) s = (s + i * 7) % 1000003; console.log([1 + 2 * 3, s].join(","))' ) 2>&1 | tail -5
```

The number after the comma must be identical to Step 2.
