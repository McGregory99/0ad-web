# Runbook T4.3j — Serve a deflated public.zip (worker t41, port 8102)

Read `runbooks/_wave5-common.md` first. Report: `reports/T4.3j.md`. No code edits.

Background (supervisor): the release `public.zip` stores every member uncompressed. Textures are
217 MB of the 289 MB a match downloads, and they deflate to ~58 %. The supervisor added
`tools/wasm/recompress-zip.py` and changed `tools/wasm/build-engine.sh` so the web build serves
`upstream/binaries/system-wasm/public-deflate.zip` (same files, deflated) as `mods/public/public.zip`.
The engine inflates zip members itself, so nothing else changes.

## Step 1 — Build
Web build with the BUILD command from `_wave5-common.md` (task `T4.3j`). It may wait a few minutes
for the lock (the supervisor is generating the deflated archive). Report EXIT and the log tail.
Then report:
```bash
ls -lL runs/web-t41/mods/public/public.zip upstream/binaries/data/mods/public/public.zip
readlink runs/web-t41/mods/public/public.zip
cat runs/web-t41/remote-files.json
```
Expected: the served file is `public-deflate.zip`, clearly smaller than 3,508,827,314 bytes, and the
`size` in remote-files.json equals its `ls -lL` size. If not, STOP.

## Step 2 — Cold run to the match
Exactly as T4.3h Step 4 (`runbooks/T4.3h-map-settings-index.md`): cold run with `remotelog=1`,
output `runs/T4.3j/first`, port 8102, `shot:setup` after `wait:8`, `stats` after the menu and in the
match, and the `evalfile:runs/T4.3c/dump.js` dump at the end. Use the same query and START.

append `,reload,wait:25,stats,$START,wait:40,stats,shot:game2` (output `runs/T4.3j/warm`).
Report the stats lines (look at `persistentHits` and `bytes`).
