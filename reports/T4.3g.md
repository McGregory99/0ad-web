## ICU / L10n check

A narrower grep on the same three logs (**observed**):

```
grep -inE 'icu|l10n|locale' runs/T4.3g/<run>/console.log
```

printed **nothing** for en, de and es (count = 0 each). So:

- No ICU data-load failure: nothing like `U_MISSING_RESOURCE_ERROR`, `Unable to open …icudt68l.dat`,
  or `Locale` errors appears in any run (**observed**). The filtered 4.3 MB file was accepted by the
  engine in all three runs.
- No L10n/translation errors in the console (**observed**).
- **Inferred**: the absence of ICU errors is consistent with the T4.3d analysis (only locale,
  display-name, date, calendar, time-zone and number data are needed); the removed collation /
  break-iteration / transliteration / converter / unit / rbnf data was not touched by the game.

What the logs do contain (**observed**, identical in all runs, unrelated to ICU):

- `ERROR: Failed to query audio device names` (headless audio) and
  `Failed to query SDL WM info: That operation is not supported`.
- Two `404` network errors per run (the log line does not include the URL).
- After `GAME STARTED`, a large volume of WebGL errors:
  `CShaderProgramGLSL::Link: unsupported uniform type: 0x8b62` and
  `CDeviceCommandContext::SetTexture: expected sampler at binding slot`, then
  `WebGL: too many errors, no more errors will be reported to the console for this context.`
  Total lines matching `error` (case-insensitive): en 45052, de 31620, es 42419 (**observed**).
  **Inferred**: these are the pre-existing WebGL/GLSL uniform-typing issue in the browser renderer,
  not an ICU or locale problem; they occur in all three locales and after the game has started.
