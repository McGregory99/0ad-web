**observed** pre-check: `lsof -nP -iTCP:8111 -sTCP:LISTEN` and `:8199` both exit 1 (free) before the runs.

### a) regression, no SITE_URL

```bash
mkdir -p runs/T4.5a
node tools/web/chrome-shot.mjs runs/web-t05 runs/T4.5a/plain 'wait:20,shot:menu' '?arg=-mod=public&arg=-conf=windowed:true' 8111 > runs/T4.5a/plain.log 2>&1; echo EXIT=$?; tail -5 runs/T4.5a/plain.log
```

- **observed** `EXIT=0`; `tail -5` printed nothing because `plain.log` is 0 bytes (`wc -c` → `0`):
  no `site url:` line, i.e. the unset path stayed silent and unchanged.
- **observed** the run loaded from the spawned `serve.mjs` on 8111 (page booted, see console log below).
- **derived** that server was shut down by `chrome-shot`'s cleanup: the later `serve.mjs` in (b)
  bound 8111 successfully one second after start (`runs/T4.5a/serve.log` has the `serving ...` line).

### b) SITE_URL against a server started by me

```bash
node tools/spikes/serve.mjs runs/web-t05 8111 > runs/T4.5a/serve.log 2>&1 & S=$!; sleep 1
SITE_URL=http://127.0.0.1:8111/ node tools/web/chrome-shot.mjs runs/web-t05 runs/T4.5a/url 'wait:20,shot:menu' '?arg=-mod=public&arg=-conf=windowed:true' 8199 > runs/T4.5a/url.log 2>&1; echo EXIT=$?; tail -5 runs/T4.5a/url.log
kill $S
```

- **observed** `EXIT=0`, and `runs/T4.5a/url.log` (73 bytes) contains exactly:
  `site url: http://127.0.0.1:8111/?arg=-mod=public&arg=-conf=windowed:true`
  (one `/` between SITE_URL and query, trailing `/` stripped).
- **observed** nothing listened on 8199 while (b) ran. I ran a poller in parallel, started before
  the runs: `lsof -nP -iTCP:8199 -sTCP:LISTEN` every 0.5 s for 70 s →
  `runs/T4.5a/lsof-8199.log`, 140 lines, all `none`, window `12:39:53` … `12:41:24`
  (`grep -c ' none$'` → 140, `grep -c -v ' none$'` → 0). The window covers both runs.
  So (b) used the `SITE_URL` branch (no server on its `port` argument 8199) and reached the site
  through my own `serve.mjs` on 8111.
- **observed** `kill $S` did not stop my `serve.mjs`: after the block
  `lsof -nP -iTCP:8111 -sTCP:LISTEN` still showed
  `node 90495 gcancio 12u IPv4 ... TCP 127.0.0.1:8111 (LISTEN)`, and
  `ps -o pid,ppid,lstart,command -p 90495` → `node tools/spikes/serve.mjs runs/web-t05 8111`,
  started `12:40:33`, PPID 1. **inferred** cause: `$!` in that non-interactive shell invocation
  did not resolve to the node PID, so the signal hit a wrapper. I stopped it with a targeted
  `kill 90495` (**not** `pkill`/`killall`) → `KILL_EXIT=0`, then
  `lsof -nP -iTCP:8111 -sTCP:LISTEN` exit 1 and `ps -p 90495` exit 1: port free again.
  This stray listener was on 8111 (port a), never on 8199, so it does not affect the (b) check.
