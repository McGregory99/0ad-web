# Runbook T4.5a — chrome-shot can drive a deployed site (worker t45)

Read `runbooks/_wave7-common.md` first. Report: `reports/T4.5a.md`. Logs: `runs/T4.5a/`.
Port: http 8111 (yours only).

## Background (supervisor)
The build will be deployed on a LAN server over https with a self-signed (Caddy internal CA)
certificate. The supervisor wants to drive real page loads against that URL with the existing
tool. Today `tools/web/chrome-shot.mjs` always starts `tools/spikes/serve.mjs` on the given port
(line ~45) and navigates to `http://127.0.0.1:${port}/${query}` (line ~114).

## Files you may edit
- `tools/web/chrome-shot.mjs`
- new: `runs/T4.5a/*`

## Step 1 — `SITE_URL` env
In `chrome-shot.mjs`, read `process.env.SITE_URL` (for example `https://192.168.0.28:8012/`).
When it is set and non-empty:
- do NOT spawn `serve.mjs` (and do not kill it at the end; guard every use of the server
  process);
- navigate to `SITE_URL` with the query appended: make sure there is exactly one `/` between
  them (strip trailing `/` from SITE_URL, then add `/` + query);
- add `--ignore-certificate-errors` to the Chrome arguments (self-signed LAN certificate);
- `say()`/log one line at start: `site url: <the full URL>`.
When it is unset, behaviour must stay byte-for-byte the same as now (same args, same server).
Update the usage comment at the top of the file with one line about `SITE_URL`.
`node --check tools/web/chrome-shot.mjs` → exit 0.

## Step 2 — Tests
Build: `runs/web-t05` (read-only, do not rebuild anything).
```bash
mkdir -p runs/T4.5a
# a) regression, no SITE_URL
node tools/web/chrome-shot.mjs runs/web-t05 runs/T4.5a/plain 'wait:20,shot:menu' '?arg=-mod=public&arg=-conf=windowed:true' 8111 > runs/T4.5a/plain.log 2>&1; echo EXIT=$?; tail -5 runs/T4.5a/plain.log
# b) SITE_URL against a server you start yourself
node tools/spikes/serve.mjs runs/web-t05 8111 > runs/T4.5a/serve.log 2>&1 & S=$!; sleep 1
SITE_URL=http://127.0.0.1:8111/ node tools/web/chrome-shot.mjs runs/web-t05 runs/T4.5a/url 'wait:20,shot:menu' '?arg=-mod=public&arg=-conf=windowed:true' 8199 > runs/T4.5a/url.log 2>&1; echo EXIT=$?; tail -5 runs/T4.5a/url.log
kill $S
```
Expected: both EXIT=0, both logs reach the main menu the same way (compare the last lines of
`plain/console.log` and `url/console.log`), `url.log` has the `site url:` line, and nothing
listened on 8199 during (b) (check with `lsof -nP -iTCP:8199 -sTCP:LISTEN` while it runs, or
explain how you checked). Never use `pkill`/`killall`.
