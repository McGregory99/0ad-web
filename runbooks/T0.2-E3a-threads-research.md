# Runbook T0.2-E3a — Research: what does a threads-capable SpiderMonkey build need? (READ-ONLY)

The engine uses threads, so the final wasm needs shared memory. wasm-ld refused our SpiderMonkey
objects because they lack the `atomics` and `bulk-memory` features. Before changing the build,
the supervisor needs facts. Only READ and REPORT. Do not install, build or edit anything.

- Root: `~/DEVELOPMENT/0ad-web` (ROOT) — Report: `ROOT/reports/T0.2-E3a.md`

Every shell must start with:

```bash
R=~/DEVELOPMENT/0ad-web
M=$R/wasm/spidermonkey/mozjs-128.13.0
export RUSTUP_HOME=$R/tools/rustup CARGO_HOME=$R/tools/cargo
TC=$R/tools/rustup/toolchains/1.79.0-aarch64-apple-darwin
```

## Step 1 — Rust targets available in our private toolchain

```bash
ls $TC/lib/rustlib/
$TC/bin/rustc --print target-list | grep -E '^wasm32'
$R/tools/cargo/bin/rustup target list --toolchain 1.79.0-aarch64-apple-darwin 2>&1 | grep -E 'wasm32' || echo "rustup binary not usable here"
ls $R/tools/cargo/bin
```

## Step 2 — wasi-sdk sysroots and targets

```bash
ls $R/tools/wasi-sdk/share/wasi-sysroot/lib/ $R/tools/wasi-sdk/share/wasi-sysroot/include/
ls $R/tools/wasi-sdk/lib/clang/*/lib/ 2>/dev/null
$R/tools/wasi-sdk/bin/clang --target=wasm32-wasi-threads -print-target-triple 2>&1 | head -2
$R/tools/wasi-sdk/bin/clang --target=wasm32-wasip1-threads -print-target-triple 2>&1 | head -2
```

## Step 3 — How SpiderMonkey's build turns the target into C and Rust settings

```bash
cd $M
grep -rn 'wasi' build/moz.configure/init.configure | head -30
grep -rn 'wasi' build/moz.configure/rust.configure | head -30
grep -rn 'wasi' build/moz.configure/toolchain.configure | head -20
grep -rn 'atomics\|bulk-memory\|wasi-threads\|wasip1' build/moz.configure/*.configure js/moz.configure | head -30
grep -rn 'RUST_TARGET\|rust_target' build/moz.configure/rust.configure | head -20
```

## Step 4 — Does SpiderMonkey code assume no threads on wasi?

```bash
cd $M
grep -rn '__wasi__' js/src mozglue mfbt --include='*.h' --include='*.cpp' | grep -iE 'thread|mutex|atomic|condvar' | head -40
grep -rln '__wasi__' js/src mozglue mfbt --include='*.h' --include='*.cpp' | wc -l
ls mozglue/misc | grep -iE 'mutex|condition|thread'
```
