**Relevant line in the supervisor's `build-wasi.sh` (observed, line 24):**
```bash
export RUSTFLAGS="-C target-feature=+atomics,+bulk-memory"
```

**Derived (diagnosis):** `mozbuild` treats `RUSTFLAGS` from the environment as a *configure
option* declared to take exactly one value. The exported value
`-C target-feature=+atomics,+bulk-memory` contains a **space**, so mozbuild's option parser splits
it into two values and raises `InvalidOptionError: RUSTFLAGS takes 1 value` before any build work
starts. This is why the build stops at 0:00.55 and why `libjs_static.a` was not regenerated.

**Inferred (not verified):** passing the flag without an internal space — e.g.
`-Ctarget-feature=+atomics,+bulk-memory` (the `-C` attached to its argument) — would present a
single token to mozbuild. I did not try this; the runbook forbids changing flags.
