Why each kept category (**inferred**, based on ICU 68 data layout and the Step 1 usage):

- `misc` — shared metadata: timezone alias/meta data, likely-subtags and the `supplementalData`
  that `icu::Locale`, `TimeZone` and `SimpleDateFormat` consult.
- `zone_tree` — timezone names/offsets for `icu::TimeZone::getGMT` and date formatting with zones.
- `curr_tree` — currency data referenced by date/number patterns and locale data.
- `lang_tree` — language display names required by `locale.getDisplayName(...)` (language selector UI).
- `region_tree` — region/country display names required by the same `getDisplayName` call.
- `locale_tree` — per-locale date, time and number patterns used by `SimpleDateFormat` /
  `NumberFormat::createInstance` (the `includeChildren: true` locale filter keeps `en_GB`,
  `pt_BR`, `pt_PT`, `zh_TW` and drops the other ~700 ICU locales).

Why each excluded feature (**inferred**, each backed by "no hits" in Step 1):

- `coll_tree` — collation data (~7 MB of the file); the engine never calls `ucol_*`/`icu::Collator`.
- `brkitr_tree`, `brkitr_rules`, `brkitr_dictionaries`, `dict` — break iteration and its dictionary
  data (~4-5 MB); no `ubrk_*`/`icu::BreakIterator` and no dictionary-based segmentation.
- `translit` — transliteration rules (~1 MB); no `utrans_*`/`icu::Transliterator`.
- `rbnf_tree` — rule-based number spellout; no `icu::RuleBasedNumberFormat`.
- `conversion` — charset converter tables (`ucnv_*`); the engine uses `UnicodeString::fromUTF8`
  only, so no converters.
- `unames` — Unicode character names; never queried.
- `unit_tree` — measurement-unit formatting; no `icu::MeasureUnit`/`icu::NumberFormatter` unit usage.
