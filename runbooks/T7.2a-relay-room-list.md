## Step 1 — Rooms, META message, `GET /rooms`
In `relay.mjs`:
1. Room range: new options `roomMin` / `roomMax` (env `RELAY_ROOM_MIN` / `RELAY_ROOM_MAX`,
   defaults 20700 / 20999). A session is a **room** when its bound UDP port is inside
   `roomMin..roomMax` (both ends included). Add both env lines to the header comment.
2. New message type `META = 0x03` (export it like the others), client → relay:
   `[0x03][utf-8 JSON object]`, total message length at most 513 bytes (1 + 512).
   - Before the session is bound it is the existing rule: the first message must be BIND (fail).
   - After BOUND, META is **dropped** (`stats.dropped++`, the session stays open) when: the
     session is not a room, the message is longer than 513 bytes, the text is not valid JSON,
     or the JSON is not a plain object (arrays and null are not objects here).
   - Otherwise the relay stores, for that session, replacing any earlier META:
     `name`: if `typeof name === 'string'`, remove control characters (U+0000..U+001F and U+007F),
     trim, cut to the first 40 characters (`Array.from(s).slice(0, 40).join('')`); an empty result
     or a non-string means `null`.
     `players`: if `Number.isInteger(players) && players >= 0 && players <= 64` that number,
     otherwise `null`. Every other field is ignored.
   - META while the UDP socket is still binding is dropped like any other message (existing rule).
3. HTTP on the same server (`server.on('request', ...)`; WebSocket upgrades keep working):
   - `GET /rooms` → status 200, body
     `{"rooms":[{"code":20705,"name":"Ana's game","players":2,"age":12}, ...]}`: one entry per open
     room session, sorted by `code` ascending; `name` / `players` are `null` until a META sets them;
     `age` = whole seconds since BOUND (`Math.floor`). Headers: `Content-Type: application/json`,
     `Cache-Control: no-store`, `Access-Control-Allow-Origin: *`,
     `Cross-Origin-Resource-Policy: cross-origin`.
   - A query string is ignored (`/rooms?x=1` is `/rooms`).
   - Any other path → 404 (plain text body `not found`). Any other method on `/rooms` → 405 with
     header `Allow: GET`.
   - A closed session disappears from the list at once (same place the UDP port is freed).
4. In `PROTOCOL.md`: add the META row to the message table, and a short `## Room list` section
   (room range and its env vars, `GET /rooms` response with an example, the CORS/CORP headers,
   and that names are user text: clients must display them as plain text).
`node --check tools/relay/relay.mjs` → exit 0.

## Step 2 — Tests (in `relay.test.mjs`, keep every existing test unchanged)
Use the global `fetch` for HTTP. For room tests, get a free UDP port P first (bind a `dgram`
socket to port 0, read the port, close it) and start a separate relay with
`{ port: 0, roomMin: P, roomMax: P, log: () => {} }` (close it at the end of the test), then
`BIND P`. One test per rule:
1. `GET /rooms` on a relay with no sessions → 200, `{"rooms":[]}`, and the four headers above.
2. A room session is listed with `code` P, `name` null, `players` null, `age` 0 or 1; after
   `META {"name":"Ana's game","players":2}` (wait ~100 ms) → name and players set; after closing
   the WebSocket (await `closed`, then ~100 ms) → the list is empty again.
3. A session bound outside the room range (`BIND 0` on the shared relay) is not listed, and its
   META is dropped (`stats.dropped` grows by 1) without closing the session (a SEND afterwards
   still reaches a UDP peer).
4. Drops without closing on a room session: invalid JSON, a JSON array, and a 514-byte META;
   each grows `stats.dropped` by 1 and the listed name stays the last valid one.
5. Name cleaning: `{"name":"  a\u0001b  ","players":99}` → name `"ab"`, players `null`; a 50-char
   name is cut to 40 characters; `{"name":5}` → name `null`.
6. META as the very first message → ERROR and the WebSocket closes (existing rule still holds).
7. `GET /nope` → 404; `POST /rooms` → 405 with `Allow: GET`; `GET /rooms?x=1` → 200.
