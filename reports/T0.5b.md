## Speed-up PBL on vs off (derived)

Off baseline: total 288.4 s, avg 23.22 ms, p50 8.73 ms, p99 218.87 ms, max 2453.45 ms,
>50 ms 1215, >100 ms 452, >200 ms 142 (one sample).

PBL-on medians of the 3 runs: total 198.8 s, avg 16.01 ms, p50 6.52 ms, p99 138.21 ms,
max 1510.23 ms, >50 ms 713, >100 ms 225, >200 ms 65.

| metric | off | PBL median | speed-up (derived) |
|--------|-----|------------|--------------------|
| total replay time | 288.4 s | 198.8 s | **1.45×** |
| avg turn | 23.22 ms | 16.01 ms | 1.45× |
| p50 | 8.73 ms | 6.52 ms | 1.34× |
| p99 | 218.87 ms | 138.21 ms | 1.58× |
| max turn | 2453.45 ms | 1510.23 ms | 1.62× |
| turns > 50 ms | 1215 | 713 | 1.70× fewer |
| turns > 100 ms | 452 | 225 | 2.01× fewer |
| turns > 200 ms | 142 | 65 | 2.18× fewer |

Per-run totals vs off (derived): 288.4/198.8 = 1.451, 288.4/196.0 = 1.471, 288.4/225.6 = 1.278 —
the slowest PBL run is still 1.28× faster than the off run, so the gain is not a single lucky run.
The p50 gain (1.34×) is smaller than the tail gains (1.58× p99, 2.18× fewer >200 ms turns):
**inferred**, PBL mostly removes interpreter overhead on long/slow turns while the fixed per-turn
cost (AI scripts, simulation) stays the same. Max-turn values are noisy in both modes (off 2453 ms,
PBL 1144–1696 ms) — one outlier turn dominates each run, so the max figure is the least reliable
of the numbers above (**inferred**).

Caveat (**derived**): the off side is a single run (the runbook asks for one), while the PBL side
has three; run-to-run spread on the PBL side is 196.0–225.6 s (±7.5%), so the true speed-up is
roughly **1.3–1.5×**, not an exact 1.45×.
