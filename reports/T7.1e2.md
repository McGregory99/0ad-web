### Three fixes to my own script (wave-7 allows 3 retries; each is backed by an observed failure)

The runbook's literal step sequence did not reach the match. Each failing run is kept, not
overwritten: `runs/T7.1e2/gui-attempt{1,2,3}/` + `gui-attempt{1,2,3}.log`; the passing run is
`runs/T7.1e2/gui/`.

1. **Duplicate player name.** Attempt 1 reached the host's game setup page but the client was
   disconnected 0.3 s after joining.
   **Observed** — `runs/T7.1e2/gui-attempt1/client.mainlog.html`:
   `Net message: ({reason:8, status:"disconnected", type:"netstatus"})`, and the host
   authenticated as `m_Name: web_user`. `upstream/source/network/NetHost.h` lists
   `NDR_PLAYERNAME_IN_USE` at index 8 (**observed**), and `NetServer.cpp:1032` disconnects with
   it when a session name is already in use; `network.duplicateplayernames = "false"` is the
   build's default (**observed** in the host mainlog). Both pages therefore defaulted to
   `web_user`.
   **Fix 1** — the client page query got `&arg=-conf=playername:client`. Attempt 2 still failed
   with `reason:8` (**observed**).
2. **Wrong config key.** `gui/common/functions_utility.js` (read from
   `upstream/binaries/system-wasm/public-medium.zip`) has
   `multiplayerName() { return Engine.ConfigDB_GetValue("user", "playername.multiplayer") || Engine.GetSystemUsername(); }`
   (**observed**), and the join dialog's name field loads `multiplayerName()`
   (`gui/gamesetup_mp/gamesetup_mp.xml`, `<action on="Load">`) — so `playername` was the wrong key.
   **Fix 2** — `&arg=-conf=playername.multiplayer:client`. Attempt 3 joined and stayed connected,
   but did not reach the match.
3. **Client not ready.** Attempt 3: client and host both connected at the end (client sent 1743 /
   received 1740 datagrams) but neither logged `GAME STARTED`.
   **Observed** — `runs/T7.1e2/gui-attempt3/client.mainlog.html`, `CPlayerAssignmentMessage`:
   `m_Name: client, m_PlayerID: 2, m_Status: 0` and `m_Name: web_user, m_PlayerID: 1, m_Status: 2`;
   no `CReadyMessage` from the client in the host mainlog. Status 0 = not ready, so the host's
   START was disabled and the `1185:681` click did nothing (**derived** from the status values and
   the absence of `GAME STARTED`).
   **Fix 3** — after the 20 s join wait, click `1185:681` on the client page (the bottom-right
   button is "I'm ready" for a joining client), wait 3 s, then click `1185:681` on the host.
   Attempt 4 (the passing run) started the match on both pages.

No engine code, no GUI overlay code and no other file was touched. No `MP_GUI` behaviour of the
existing autostart paths changed: the branch is `if (MP_GUI) … else if (MP_NATIVE === 'host') …`.
