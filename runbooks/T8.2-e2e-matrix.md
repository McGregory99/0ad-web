# Runbook T8.2 — One command checks the game in Chrome and Firefox (worker t82)

Read `runbooks/_wave7-common.md` first. Report: `reports/T8.2.md`. Logs: `runs/T8.2/`.

## Background (supervisor)

Chrome and Firefox both play a skirmish at ~60 fps on this Mac (checked by hand, log L42).
There is no single automated check. `tools/web/chrome-shot.mjs` and
`tools/web/firefox-shot.mjs` each serve a build, run a script of steps and write
`<outdir>/console.log` (read their header comments for the steps and env variables).
Goal: `tools/web/e2e.mjs` runs the same scenario in both browsers and prints PASS/FAIL per
browser plus a summary JSON, exit code 0 only if all pass.

Scenario (1280x720, full game query `'?arg=-mod=public&arg=-conf=windowed:true'`):
boot → main menu → single player → skirmish → START (default map) → in the match →
measure fps → screenshot. START clicks:
`click:491:553,wait:2,click:180:221,wait:3,click:418:221,wait:8,click:1185:681`.

## Step 1 — Learn the output (manual runs)
```bash
mkdir -p runs/T8.2
WORKER=t82 tools/wasm/with-lock.sh sh -c 'rm -r runs/web-t82 2>/dev/null; cp -RP runs/web-t71b-final runs/web-t82'
S='wait:25,shot:menu,click:491:553,wait:2,click:180:221,wait:3,click:418:221,wait:8,click:1185:681,wait:40,stats,fps:10,shot:game'
Q='?arg=-mod=public&arg=-conf=windowed:true'
CHROME_GPU=1 node tools/web/chrome-shot.mjs runs/web-t82 runs/T8.2/manual-chrome "$S" "$Q" 8107 > runs/T8.2/manual-chrome.log 2>&1; echo EXIT=$?
node tools/web/firefox-shot.mjs runs/web-t82 runs/T8.2/manual-firefox "$S" "$Q" 8107 > runs/T8.2/manual-firefox.log 2>&1; echo EXIT=$?
```
Then look at both `console.log` files: find (a) the line that shows the match started
(`GAME STARTED`), (b) the fps line written by the `fps:` step (its exact format), (c) error
lines (`exception`, `error`, `ERROR`). Open `menu.png` and `game.png` of each (Read tool) and
say what they show. Write all formats into the report (observed). If a browser does not reach
the match, STOP after reporting both runs.

## Step 2 — Write `tools/web/e2e.mjs`
Usage: `node tools/web/e2e.mjs <build dir> <outdir> [port, default 8107]`.
Env: `E2E_BROWSERS` (comma list, default `chrome,firefox`), `E2E_MIN_FPS` (default 30),
`E2E_MATCH_WAIT` (seconds in the match before measuring, default 40).
Behaviour:
- Header comment in the style of the other tools (purpose, usage, env, outputs, exit code).
- For each browser, run the matching shot tool as a child process (`spawn` of `node` with the
  script path, the build dir, `<outdir>/<browser>`, the step script and the query; Chrome with
  env `CHROME_GPU=1`), sequentially (one browser at a time), and wait for it to exit.
- Parse that browser's `console.log`: `reachedMatch` (a `GAME STARTED` line), the fps numbers
  from the fps line (at least `fps`, `p99` and `max` if present), `errorLines`
  (exceptions and error lines, first 20; ignore the known harmless AI worker message
  `Cannot read properties of null (reading 'init')` but count it separately as
  `knownAiWorkerError`), and the tool's exit code.
- Browser PASS = tool exit 0, reached the match, fps >= `E2E_MIN_FPS`, no exception lines.
- Write `<outdir>/summary.json` with one object per browser and `pass` overall; print one line
  per browser `chrome: PASS fps=…` / `firefox: FAIL (reason)` and finally `PASS=true|false`.
- Exit 0 only if every selected browser passed.
`node --check tools/web/e2e.mjs; echo EXIT=$?` → 0.

## Step 4 — It catches a broken build
Make a broken copy and check the tool fails:
```bash
cp -RP runs/web-t82 runs/web-t82-broken && printf 'garbage' > runs/web-t82-broken/pyrogenesis.wasm.broken && mv runs/web-t82-broken/pyrogenesis.wasm runs/web-t82-broken/pyrogenesis.wasm.orig && mv runs/web-t82-broken/pyrogenesis.wasm.broken runs/web-t82-broken/pyrogenesis.wasm
E2E_BROWSERS=chrome node tools/web/e2e.mjs runs/web-t82-broken runs/T8.2/e2e-broken 8107 > runs/T8.2/e2e-broken.log 2>&1; echo EXIT=$?; tail -3 runs/T8.2/e2e-broken.log
```
Expected: EXIT=1 and `PASS=false`. (If `pyrogenesis.wasm` is a symlink, `mv` moves the link,
which is fine: the original file is untouched. Report `ls -l` of both files.) Leave
`runs/web-t82-broken` in place and name it in the report; the supervisor removes it.
