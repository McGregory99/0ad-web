# Runbook T4.3h — Map settings index instead of downloading every map (worker t41, port 8102)

Read `runbooks/_wave5-common.md` first. Report: `reports/T4.3h.md`.

Context (your T4.3f Part B): the game setup screen calls `LoadMapSettings` for every map;
`CMapSummaryReader::LoadMap` (`graphics/MapReader.cpp:440`) reads the whole
`<map>.xml.cached.xmb` only to keep the `<ScriptSettings>` text. 77 skirmish maps = 82 MB.
Goal: at build time, extract every map's `<ScriptSettings>` text into one small index file that
the web build preloads; in the Emscripten build, `LoadMap` answers from the index and only falls
back to the XMB when the map is not in the index.

Allowed edits: new `tools/wasm/map-settings-index.py`; `tools/wasm/build-engine.sh` (web profile
only: run the script, add one `--preload-file`); `upstream/source/graphics/MapReader.cpp`
(code inside `#ifdef __EMSCRIPTEN__` only). The supervisor commits (git is owned by the supervisor).

## Step 1 — Index generator
`tools/wasm/map-settings-index.py <public.zip> <out-file>`:
- For every zip member matching `maps/**/*.xml` (not `.cached.`), parse the XML with
  `xml.etree.ElementTree` and take the text of the root's direct child `ScriptSettings`
  (skip files without it; skip and count files that fail to parse).
- Output format (simple to read from C++), for each map, sorted by path:
  `<path>\n<byte length of settings as UTF-8>\n<settings bytes>\n`
  where `<path>` is the VFS path, e.g. `maps/skirmishes/greek_acropolis_4p.xml`.
- Print: maps found, written, skipped (no ScriptSettings), failed, total output bytes.
Run it on public.zip into `runs/T4.3h/mapsettings.idx` and paste the printout.

## Step 2 — Build integration
In the web profile of `build-engine.sh`: generate `$OUT/mapsettings.idx` from `$PUBLIC_ZIP` when it
is missing or older than public.zip or the script, and add
`--preload-file $OUT/mapsettings.idx@/0ad/mapsettings.idx`. Find how `$PUBLIC_ZIP` and `$OUT` are
defined in the script; the preload must be inside the web LDFLAGS like the ICU one.

## Step 3 — Engine lookup
In `CMapSummaryReader::LoadMap`, under `#ifdef __EMSCRIPTEN__`, before the XMB load:
- A function-local `static std::unordered_map<std::string, std::string>` filled once from
  `/0ad/mapsettings.idx` with `std::ifstream` (binary) in the format above. If the file is missing,
  the map stays empty.
- Look up `filename_xml.string8()` (check the exact VfsPath → string method used elsewhere in
  MapReader.cpp). If found: `m_ScriptSettings = <text>` (convert to the member's type the same way
  the XMB branch does, e.g. `CStr` / UTF-8 → wide if needed) and `return PSRETURN_OK;`.
Keep the existing code as the fallback.

## Step 4 — Build and measure
Web build (task T4.3h). Then a cold run to the match with `remotelog=1` (as in T4.3c Step 3,
output `runs/T4.3h/first`, port 8102), plus `shot:setup` taken after the single-player →
skirmish clicks and before the final start click (insert it into START after `wait:8`).
Report: stats lines (menu and match), total bytes vs T4.3f bs64 (365.0 MB), the sum of
`maps/skirmishes` bytesFetched from remotelog (expected near 0 except the chosen map), console
errors, and whether `GAME STARTED, ALL INIT COMPLETE` appears.
