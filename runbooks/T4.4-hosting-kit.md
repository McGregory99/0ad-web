# Runbook T4.4 prep — Hosting kit, nothing published (worker t44)

Read `runbooks/_wave7-common.md` first. Report: `reports/T4.4-prep.md`. Logs: `runs/T4.4/`.

## Background (supervisor)

Publishing the game (T4.4) waits for the user's OK. This task prepares everything so that
publishing is one short step later. **You must not upload, deploy, push or contact any
remote server.** Everything runs on 127.0.0.1.

What a host must do for this build (known facts):
- Every page response needs `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: require-corp` (SharedArrayBuffer for pthreads), and every
  file `Cross-Origin-Resource-Policy: same-origin`.
- `.wasm` must be served as `application/wasm`; `.js` as `text/javascript`.
- `mods/public/public.zip` and `mods/mod/mod.zip` are read with HTTP Range requests
  (64 KiB blocks), so the server must answer `Range` with `206 Partial Content` and
  `Accept-Ranges: bytes`. Compression must be OFF for the zips (Range on gzip breaks).
- The game's file list is in `remote-files.json` next to the page.
- The local test server `tools/spikes/serve.mjs` already does all of this; read it.
- Multiplayer needs the relay `tools/relay/relay.mjs` (read its header: `RELAY_TLS_CERT`,
  `RELAY_TLS_KEY`, `RELAY_PUBLIC_IP`, `RELAY_UDP_MIN/MAX`, `RELAY_DEST`) reachable at
  `wss://<page host>:20600/` by default (`tools/relay/PROTOCOL.md`), plus the UDP port range
  open in the firewall.
- The licenses page has a placeholder `SOURCE_URL` (`tools/wasm/web/licenses/licenses.html`)
  that must become the public URL of the source code (GPL).

## Step 2 — `tools/host/package-site.sh`
Usage: `tools/host/package-site.sh <web build dir> <out dir> <source url>`.
- Refuses to run if `<out dir>` exists (exit 2 with a message) — never deletes anything.
- Copies the build with symlinks resolved (`cp -RL`), so the out dir is self-contained.
- Replaces every `SOURCE_URL` in the copied `licenses/licenses.html` (find its real path in the
  build first) with `<source url>` (`sed` into a temp file then `mv`; macOS sed needs `-i ''`
  so prefer the temp-file way).
- Writes `<out dir>/SHA256SUMS` (`shasum -a 256` of every file, relative paths).
- Prints the out dir size. `set -eu` at the top. Header comment with usage.
Test:
```bash
sh tools/host/package-site.sh runs/web-t44 runs/T4.4/site https://example.invalid/0ad-web-source > runs/T4.4/package.log 2>&1; echo EXIT=$?; tail -3 runs/T4.4/package.log
grep -c "example.invalid" $(find runs/T4.4/site -name licenses.html); grep -c SOURCE_URL $(find runs/T4.4/site -name licenses.html)
find runs/T4.4/site -type l | wc -l
sh tools/host/package-site.sh runs/web-t44 runs/T4.4/site x; echo EXIT=$?
```
Expected: EXIT=0; replaced count ≥ 1, `SOURCE_URL` count 0, symlinks 0; second run EXIT=2.

## Step 3 — `tools/host/check-site.mjs`
Usage: `node tools/host/check-site.mjs <base url>` (e.g. `http://127.0.0.1:8108/`).
Checks, each printed as `ok`/`FAIL` with the observed value:
1. `GET <base>` (the page): status 200, COOP `same-origin`, COEP `require-corp`.
2. `GET <base>pyrogenesis.wasm`: content type `application/wasm`, CORP present (cancel the
   body after reading the headers: `await res.body.cancel()`).
3. `GET <base>pyrogenesis.js`: content type contains `javascript`.
4. `GET <base>remote-files.json`: 200, valid JSON; take the first listed zip path from it
   (read the JSON's shape first and say what it is).
5. That zip with `Range: bytes=0-65535`: status 206, `Content-Range` present, body length
   65536, no `Content-Encoding`.
6. `GET <base>licenses/licenses.html` (or the real path): 200 and it does not contain
   `SOURCE_URL`.
Exit 0 if all ok, 1 otherwise. Use only Node built-ins (`fetch` is built in). Header comment.
Test against the local server:
```bash
node tools/spikes/serve.mjs runs/T4.4/site 8108 > runs/T4.4/serve.log 2>&1 & S=$!; sleep 1
node tools/host/check-site.mjs http://127.0.0.1:8108/ > runs/T4.4/check.log 2>&1; echo EXIT=$?; cat runs/T4.4/check.log
kill $S
```
Then prove it catches a bad
server: serve `runs/T4.4/site` with Python's plain server (no COOP/COEP) and check it fails:
```bash
(cd runs/T4.4/site && python3 -I -m http.server 8108 --bind 127.0.0.1 > ../plain.log 2>&1) & P=$!; sleep 1
node tools/host/check-site.mjs http://127.0.0.1:8108/ > runs/T4.4/check-plain.log 2>&1; echo EXIT=$?; cat runs/T4.4/check-plain.log
kill $P
```
Expected: first check EXIT=0 (all ok); plain server EXIT=1 with COOP/COEP FAIL.

## Step 4 — Server and relay config (files only, nothing started)
- `tools/host/Caddyfile`: a Caddy v2 site block for `{$SITE_DOMAIN}` serving
  `{$SITE_ROOT}` with `file_server`, the three headers on every response,
  `application/wasm` for `*.wasm`, NO `encode` for `*.zip` (you may `encode zstd gzip` for
  other types only), `Cache-Control: public, max-age=3600` for everything except
  `*.html` (`no-cache`), and a `reverse_proxy` is NOT needed (the relay listens itself).
  Comment each block.
- `tools/host/zeroad-relay.service`: a systemd unit running
  `/usr/bin/node /opt/0ad-web/tools/relay/relay.mjs` as an unprivileged user with
  `Environment=RELAY_HOST=0.0.0.0 RELAY_PORT=20600 RELAY_UDP_MIN=20700 RELAY_UDP_MAX=20999`
  and `EnvironmentFile=-/etc/0ad-web/relay.env` (for `RELAY_PUBLIC_IP`, `RELAY_TLS_CERT`,
  `RELAY_TLS_KEY`), `Restart=on-failure`, and basic hardening
  (`NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`).
- Check the relay starts with that environment locally (no TLS):
```bash
RELAY_HOST=127.0.0.1 RELAY_PORT=20630 RELAY_UDP_MIN=20700 RELAY_UDP_MAX=20710 perl -e 'alarm shift; exec @ARGV' 3 node tools/relay/relay.mjs > runs/T4.4/relay.log 2>&1; cat runs/T4.4/relay.log
```
Expected: a `listening on ws://127.0.0.1:20630/` line.

## Step 5 — `tools/host/README.md`
Short deploy guide in English (no marketing): requirements (static host with custom headers,
a machine for the relay with a public IPv4, TLS certificate), steps:
package (`package-site.sh`) → upload the out dir → configure headers (Caddyfile or the
equivalent table for other hosts) → run `check-site.mjs <public url>` → relay: copy repo
`tools/relay/` to `/opt/0ad-web/tools/relay/`, install `ws` (`npm install ws` there), env file,
systemd unit, firewall (TCP 20600, UDP 20700-20999) → open the game with
`?relay=wss://<relay host>:20600/` if the relay is not on the page host. Include a table of
the required headers and a "Known limits" section (Safari not supported yet; ~186 MB
download for a first match). Every command in it must be one you saw work in this runbook or
marked "not tested here".
