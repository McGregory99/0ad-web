Note on the observed counts (factual, not a recommendation): all nine file-pattern
greps returned 0 because the search patterns contain `\|`, and under `grep -E`
(GNU/BSD) a backslash-escaped pipe is matched as a **literal `|` character**, not as
alternation. Verified with:
`printf 'Atlas|AtlasUI\nAtlasUI\n' | grep -E "Atlas\|AtlasUI\|ATLAS"` → no match (exit 1).
A plain substring check for the same token differs, e.g.
`grep -rIl "Atlas" source --include='*.cpp' --include='*.h' | grep -v '/tests/' | wc -l`
→ 163. The macro rows (3, 4, 5) use plain strings without `\|`, so their counts
(19 / 10 / 7) are real matches.
