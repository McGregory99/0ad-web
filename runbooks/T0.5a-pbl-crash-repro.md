# Runbook T0.5a — Reproduce the fast-interpreter (PBL) crash

Context: with SpiderMonkey's portable baseline interpreter (PBL, the default in our build) the wasm
replay crashed once at turn 4812 (`RuntimeError: unreachable`) and once at turn 4972
(`null function or function signature mismatch`). We need to know if it always crashes, where,
and with which stack. You COLLECT evidence; you do not change code and you do not debug.

- Root: `~/DEVELOPMENT/0ad-web` (ROOT). Use ONLY the copy in `ROOT/upstream/binaries/system-wasm-pbl/`
  (another worker rebuilds `system-wasm/`). Write only in `ROOT/runs/` and `mktemp -d` dirs.
- Report: `ROOT/reports/T0.5a.md`

## Step 1 — Three runs, one after another (each a few minutes; limit 20 minutes each)

```bash
cd ~/DEVELOPMENT/0ad-web/upstream/binaries/system-wasm-pbl
R=~/DEVELOPMENT/0ad-web
for i in 1 2 3; do
  H=$(mktemp -d); echo "RUN $i TEMP HOME=$H"
  HOME=$H ZEROAD_EXECUTABLE=$PWD/pyrogenesis perl -e 'alarm shift; exec @ARGV' 1200 \
    node pyrogenesis -replay="$R/fixtures/reference-replay/commands.txt" > $R/runs/T0.5a-run$i.log 2>&1
  echo "RUN $i EXIT=$?"
done
```

## Step 2 — Evidence from each run

```bash
R=~/DEVELOPMENT/0ad-web
for i in 1 2 3; do
  L=$R/runs/T0.5a-run$i.log
  echo "=== run $i"; grep 'Final state' $L; grep -E '^Turn [0-9]+' $L | tail -1
  grep -nE 'RuntimeError|Aborted|unreachable|signature mismatch|out of memory' $L | head -5
  grep -A 30 -m1 'RuntimeError' $L | grep -E '^\s+at ' | head -30
done
```
