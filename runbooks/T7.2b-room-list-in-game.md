# Runbook T7.2b — Open games in the join dialog (worker t72b)

Read `runbooks/_wave7-common.md` first. Report: `reports/T7.2b.md`. Logs: `runs/T7.2b/`.
Ports: http 8112, relay 20660 (yours only).

## Background (supervisor)
T7.2a (`reports/T7.2a.md`, `tools/relay/PROTOCOL.md` "Room list") made the relay list its open
rooms: `GET /rooms` → `{"rooms":[{"code","name","players","age"}]}`, and a room session can name
itself with a `0x03 META` message `[0x03][utf-8 JSON object]`. Now the game uses it:
- the host announces its room name right after hosting;
- the join dialog shows a drop-down "Open games" that refreshes every 2 s; picking one puts its
  room code in the server field.
The GUI's JavaScript cannot fetch or open sockets, so two small C functions in the ENet tunnel
(built into libenet) and two engine script functions carry this.

Key facts (supervisor read them):
- `tools/wasm/enet-tunnel.c` `enet_socket_send` (~line 557-610) builds a `TunnelCommand` of
  type `TUNNEL_SEND_DATA` whose `data` is the exact WebSocket message; the I/O thread
  (`enet-tunnel.pre.js` `run()`, SEND_DATA branch) sends those bytes verbatim once the socket is
  bound (queues them before). So a META is just a SEND_DATA command whose bytes are `[0x03][json]`.
- `enet-tunnel.pre.js` top block (main thread) defines `Module.zeroadNet = { relayUrl, ... }`.
- Engine script functions for the network live in
  `upstream/source/network/scripting/JSInterface_Network.cpp` (`RegisterScriptFunctions`, line
  ~336, `ScriptFunction::Register<&Func>(rq, "Name")`). Upstream patches guard web-only code with
  `#ifdef __EMSCRIPTEN__`. `upstream/` is a git checkout with our patches applied: after editing,
  regenerate the new patch with
  `git -C upstream diff -- source/network/scripting/JSInterface_Network.cpp > patches/upstream/0025-emscripten-room-list.patch`
  (check first that this file is not already touched by an older patch:
  `grep -l JSInterface_Network patches/upstream/*.patch` must print nothing; if it prints a
  patch, STOP and report).
- The join dialog XML is in `data/mods/public/public.zip` (`gui/gamesetup_mp/gamesetup_mp.xml`).
  Files under `tools/wasm/web/overlay/public/` replace files of the public mod in the web build
  (`build-engine.sh` line ~66). Join page rows (dialog coordinates): name `40..64`, server
  `80..104`, port label `20 116 50% 146` + `joinPort` input `50%+10 120 100%-20 144`.
- `escapeText(text)` exists in `gui/common/functions_utility.js` (escapes GUI markup like
  `[font=...]`); room names are user text and MUST go through it before display.

## Step 1 — Tunnel C API (`enet-tunnel.c`, `enet-tunnel.pre.js`)
1. `int zeroad_net_room_meta (int port, const char * json)`: under the tunnel lock, find the open,
   not failed tunnel socket whose bound UDP port is `port` (read how `zeroad_net_bound` stores
   it; if the port is not stored, store it there). None, `json == NULL`, or `strlen(json) > 512`
   → return -1. Otherwise post one `TUNNEL_SEND_DATA` command for that socket (same fields as
   `enet_socket_send`) whose data is `0x03` followed by the JSON bytes (no NUL), return 0.
   Mark it `EMSCRIPTEN_KEEPALIVE` like the other exported functions if they are.
2. `char * zeroad_net_rooms_json (void)`: an `EM_JS` (main thread) that returns
   `stringToNewUTF8(text)` of the last room list text fetched from the relay (`""` before the
   first answer or after a failed fetch), and starts a new fetch when none is running and the
   last one started more than 2000 ms ago. The caller frees the result with `free`.
   The fetch URL is the relay URL with `ws` → `http` / `wss` → `https` and the path `rooms`
   (exactly one `/` before it, e.g. `wss://h:20600/` → `https://h:20600/rooms`), with
   `{ cache: 'no-store' }`; keep the response text only if `response.ok`. Put the cache and the
   fetch logic in `Module.zeroadNet` (top block of `enet-tunnel.pre.js`, e.g.
   `Module.zeroadNet.roomsText()`), and make the EM_JS call it; without `Module.zeroadNet` it
   returns `""`.
3. Declare both in the tunnel's header if it has one, otherwise the engine declares them
   `extern "C"` itself (Step 2).

## Step 2 — Engine script functions (patch 0025)
In `JSInterface_Network.cpp`, under `#ifdef __EMSCRIPTEN__`:
- `std::wstring WebRoomList()` → the text from `zeroad_net_rooms_json()` (UTF-8 → wide string the
  way the file converts strings elsewhere; free the C string).
- `bool WebRoomAnnounce(int port, const std::string& json)` → `zeroad_net_room_meta(port, json.c_str()) == 0`.
- Register them as `"WebRoomList"` and `"WebRoomAnnounce"` (only in the web build).
Regenerate the patch (command above). The native build must not change (the guard).

## Step 3 — GUI (overlay XML + `web_roomcode.js`) and unit tests
1. Copy the original XML out of `public.zip` into a `mktemp -d` dir (never extract into the repo),
   copy it to the new overlay path, then change ONLY the join page's port row: add
   `hidden="true"` to the "Server Port:" label and to `joinPort` (keep both objects, `joinPort`
   still holds the default port for "hostname without port"), and add, at the same sizes,
   a label (translatable caption `Open games:`) and
   `<object name="joinRoomList" type="dropdown" style="ModernDropDown" size="50%+10 120 100%-20 144"/>`.
   `diff` the original and the overlay and paste the diff in the report.
2. In `web_roomcode.js` add a pure function `webRoomListItems(text, escape)` →
   `{ labels: [...], codes: [...] }`: parse `text` (`""`, invalid JSON, no `rooms` array → both
   empty); for each room with an integer `code`, sorted by code: label
   `escape(name) + " (" + code + ")"` when `name` is a non-empty string, else `"Room " + code`;
   append `" — " + players + " players"` when `players` is an integer. `escape` is a function
   (the GUI passes `escapeText`).
   Tests in `roomcode.test.mjs` (identity escape `s => s` except where noted): `""` → empty;
   `"x{"` → empty; two rooms given out of order → sorted labels and codes; name null →
   `"Room 20705"`; with escape `s => "<" + s + ">"` the name is escaped; `players: 2` →
   suffix `" — 2 players"`.
3. In the install block (web build only), join page: set `joinRoomList.onTick` to a function
   that, at most every 2000 ms and only while `pageJoin` is visible, calls
   `Engine.WebRoomList()`, and when the text changed rebuilds `list` / `list_data` with
   `webRoomListItems(text, escapeText)`, keeping the selected code selected if still listed.
   No rooms → `list = ["(none)"]`, `list_data = [""]`, `enabled = false`; otherwise
   `enabled = true`. `onSelectionChange`: if the selected `list_data` is a code, set
   `joinServer.caption` to it.
4. Host: after the original `startHost` succeeds (existing wrapper), call
   `Engine.WebRoomAnnounce(port, JSON.stringify({ name: playername }))`; log its result with
   `warn("Room announce: " + result)`. Guard every new `Engine.*` call with
   `typeof Engine.WebRoomList === "function"` (same for Announce) so an older engine still works.
```bash

node --test tools/wasm/web/roomcode.test.mjs > runs/T7.2b/unit.log 2>&1; echo EXIT=$?
```

## Step 5 — mp-check additions and the GUI run
In `mp-check.mjs`, `MP_GUI` mode only (the click flow stays exactly the same):
- after the client's join dialog opens (the `418:285` click), wait 5 s and save
  `<outdir>/client-joindialog.png` (before clicking the server field);
- after the host's room code is known, fetch the relay's `/rooms` (local relay:
  `http://127.0.0.1:${RELAY_PORT}/rooms`; with `SITE_URL`: `https://<SITE_URL host>:20600/rooms`,
  certificate errors ignored for this fetch only), retrying every 2 s up to 20 s until the code
  is listed with a non-null name; `say()` the JSON; `summary.roomListed` = true/false and
  `summary.roomName`. In MP_GUI mode PASS also requires `roomListed`.
Then:
```bash
WORKER=t72b LOCK_NAME=mp tools/wasm/with-lock.sh sh -c 'MP_GUI=1 RELAY_PORT=20660 caffeinate -dims node tools/web/mp-check.mjs runs/web-t72b runs/T7.2b/gui 120 8112 > runs/T7.2b/gui.log 2>&1' & W=$!
```
Your bash tool stops commands after 900 s: poll every 60 s with `tail -3 runs/T7.2b/gui.log`
until `PASS=` appears or `kill -0 $W` fails. Expected `PASS=true`, `roomListed` true, the room
name equal to the host's player name, and a `Room announce: true` line in the host console.
Then the plain regression (no `MP_GUI`, outdir `runs/T7.2b/plain`, same background way) →
`PASS=true`. The supervisor will look at `client-joindialog.png`.
