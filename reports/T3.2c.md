**3. `USE_SHADOW_SAMPLER` was NOT defined on our build; `USE_SHADOW_PCF` IS defined.**
`renderer/SceneRenderer.cpp:233` (observed, `#if CONFIG2_GLES`):
```
233:		const bool useShadowSampler{device->GetBackend() != Renderer::Backend::Backend::GL};
```
Our WebGL build uses the `GL` backend, so `useShadowSampler` is `false` → `USE_SHADOW_SAMPLER` is never added (`SceneRenderer.cpp:237-238`). `USE_SHADOW_PCF` is added when `GetShadowPCF()` is true (`SceneRenderer.cpp:226-227`), and `binaries/data/config/default.cfg:97 shadowpcf = true`, so it IS defined — but it is useless because the PCF code sits *inside* `#if USE_SHADOW_SAMPLER` (`wasm/inventory/shaders/mod/shaders/glsl/common/shadows_fragment.h:23-31`).

**4. The depth texture gets neither `TEXTURE_COMPARE_MODE` nor LINEAR filtering on GLES.**
- Compare mode: the entire compare block is guarded by `#if !CONFIG2_GLES` — `renderer/backend/gl/Texture.cpp:318-330` (observed). So even though `ShadowMap.cpp:583-585` sets `samplerDesc.compareEnabled = true; compareOp = LESS_OR_EQUAL;`, on GLES nothing is ever sent to `glTexParameteri` for compare mode.
- Filtering: `ShadowMap.cpp:565-571` (observed) — GLES + `GL` backend → `NEAREST`.

**5. GLES-only branches that turn PCF/filtering off — three, and they compound:**
- `SceneRenderer.cpp:233`: shadow sampler disabled on the `GL` backend → the shader takes the `#else` branch of `shadows_fragment.h:26`, i.e. one `SAMPLE_2D` fetch with a hard `biasedShdwZ < tex.x` test and no PCF at all (observed in the inventory copy of `shadows_fragment.h`).
- `ShadowMap.cpp:565-571`: `NEAREST` depth filtering on GLES/GL.
- `Texture.cpp:318-330`: no hardware compare mode on GLES.
**Derived:** the blockiness is not a resolution problem — it is a *sampling* problem: no PCF, one nearest sample, no hardware compare.
